# Design

## Context

本变更只补规格，不改实现。设计部分记录的是**实现时已经做过的技术决策**——为什么长这个样子，以便下次改动时不会推翻有理有据的选择。

对应代码：
- `src/company/org.ts`：`terminateProject` / `deleteProject`
- `src/company/management-tools.ts`：`project_terminate` / `project_delete` 两个工具
- `src/server/http.ts`：`/api/message`、`/api/interrupt`
- `src/server/feed.ts`：`queued` 字段
- `ui/app.js`：`toggleFlip` / `sizeProjects` / 排队渲染

## Goals / Non-Goals

**Goals:**

- 把已经跑通的行为固化成契约，使后续改动有据可依
- 记录「两步终止/删除」与「排队可见」这两个设计决策的理由

**Non-Goals:**

- 不改任何实现
- 不引入工作流引擎

## Decisions

### 决策 1：终止与删除分两步，删除强制校验前置状态

**选择**：`project_delete` 内部校验 `status === "terminated"`，未终止直接拒绝。

**理由**：删除是不可逆破坏。如果允许一句话删掉正在跑的项目，一次误操作就会丢工作区。强制两步意味着老板必然看到过「已终止」这个中间状态。

**备选方案**：*在 UI 上做一个删除按钮 + 二次确认弹窗*。

被否决，因为：删除的后果（谁被解雇、删了哪些文件、不可恢复）用一段对话说清楚比弹窗更充分；而且对话记录天然留下了「谁在什么时候因为什么决定删除」的审计。

### 决策 2：删除文件前重新校验路径

**选择**：要求解析后的绝对路径落在 `CompanyDoc.workspaceRoot` 之下，且最后一段等于项目 slug。

**理由**：`rm -rf` 的目标来自数据库。数据库可能是旧的、从别的机器同步来的、或者被手工改过——写入时的正确性不能作为删除时的信任依据。

**代价**：移动过工作空间的库需要先修正 `workspaceRoot` 才能删除。这是有意的摩擦。

**备选方案**：*直接信 `project.workspace`*。测试时踩到过：库里的路径指向旧位置，`rm -rf` 删了另一个目录。

### 决策 3：终止时用 `abort({ background: true })`

**选择**：中断项目负责人与全部员工时带上 `background: true`。

**理由**：员工会话挂在后台锚点任务上。普通 `abort()` 不会穿透后台边界，只能停下项目负责人，员工会继续跑——「项目都停了员工还在干活」是明显的错误状态。

### 决策 4：默认排队用 `steer`，插队用中断 + 重投

**选择**：`/api/message` 默认 `whenBusy: "steer"`；`/api/interrupt` 先 `abort()` 再重新 `submit()`。

**理由**：老板的话不该排在整轮回答之后。`steer` 在本轮工具结束后插入，比 `followUp` 早得多。

插队之所以用「中断 + 重投」而不是底层已有的 steer，是因为 `steer` 再早也要等当前工具调用返回——当 CEO 卡在一个等下属回复的工具里时，那个等待可能长达几分钟。只有 `abort()` 能真的打断它。

**代价**：`abort()` 会清空队列中的其它消息，只重投被点击的那一条。这个语义在规格里明说了。

### 决策 5：翻转用三维动画 + JS 控制容器高度

**选择**：正反面绝对定位叠放，`rotateX(180deg)` 翻转；容器高度由 `sizeProjects()` 量出两面自然高度后按当前朝向设置。

**理由**：正反面内容高度不同（背面多出员工列表）。如果容器高度跟着内容走，没翻转的卡会被同行的高卡撑高。让容器高度脱离内容流、由 JS 显式控制，翻转时 `transition: height` 才有确定的起止值。

**踩过的坑**：最初把 `height` 设成 `auto` 去量自然高度，但两面都是 `position: absolute`，容器直接塌成 0。改用 `scrollHeight` 量。

## Risks / Trade-offs

**[插队会丢失队列里的其它消息]** → 规格里明确写出这一条；UI 上「立即处理」只出现在单条消息旁边，暗示它是针对这一条的。

**[删除依赖 workspaceRoot 正确]** → 校验失败时不删文件、明确报告，让老板人工处理，而不是猜。

**[翻转的高度控制依赖 JS 测量]** → 窗口尺寸变化、面板开合都会触发重新测量。若测量失败（元素不可见），卡片退回不设高度，视觉退化但不破版。
