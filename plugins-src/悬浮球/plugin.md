# 悬浮球

一颗球贴在窗口右缘，任何一屏都在（聊天、资料、设置、插件页）。球面就是应用标识本身
（`brandMarkSvg` 的 S + 蓝点，深底固定），面板抬头用同一份标识。

**桌面端**它有自己的那一扇窗（ADR-116）：置顶、跨桌面、拖到哪儿都行，透明的地方点击
直接穿到下面的应用；位置记在本机（`<appRoot>/orb-window.json`）。菜单栏 / 托盘图标左键
一下开关它，右键有菜单（显示 / 隐藏、打开 Solo、退出）；面板右键的「隐藏悬浮球」也能收。
主窗口里不再画球 —— 球只在一处。浏览器里照旧长在页面上。

- **悬停**展开面板，**点击**钉住，移开就收；**拖**到别处记住位置，
  拖出右缘就收成一条，再悬停滑回来；**右键**有菜单（打开助理私聊 / 贴边 / 回原位）。
- 面板里是**助理私聊**的最近消息、一个输入框和一支麦克风。
- 球上的数字是助理私聊的未读数 —— 和左栏那个徽标是同一份（`store.channels`）。

对话就是 Solo 自己的那一条私聊，不是另开的会话：消息走
`POST /api/channels/:id/messages`，读走 `GET /api/channels/:id`；
正在看这条私聊时面板直接用 `store.detail`（SSE 在推），不在时才按需拉、打开期间每 4 秒补一次。

## 语音

这是它的主用法：**说一句，听它答**。

- **说**：点面板里的麦克风开始录，再点一下结束（最长 30 秒）。录完自动转成文字、
  直接发进助理私聊；按 `Esc` 取消这一段。第一次按麦克风会顺手打开朗读。
- **听**：助理的新回复默认用**本地的 Kokoro 神经音色**念出来（sherpa-onnx + Kokoro-82M
  v1.1-zh，默认 `zf_001`；Apache-2.0，可商用），不是系统 `speechSynthesis` ——
  那套是拼接合成，挑什么音色都机械。回复按句子切成小片合成，第一片先出声；面板收起就停，
  正在读的时候再按麦克风会先掐掉。
  右上角的喇叭可以随时关掉 / 打开，开关记在本机（`localStorage["solo.orb"]`）。
- **换成千问云端**：设置 → 悬浮球语音 的第一段是两张卡，选「千问云端」就改走阿里云百炼的
  `qwen3-tts-flash-realtime`（48 个系统音色，含方言，默认 `Cherry` / 芊悦，语速 0.5–2×）。
  要填自己的 API Key（百炼控制台创建），存在 `<appRoot>/orb/voice.json`，只回「有没有存」，
  不回原文、不进日志。选了千问不会静默回退本机：没填 Key 时朗读直接报「千问还没填 API Key」。
  合成的文字会发到阿里云；**说**那一段仍然在本机转写。
- **音色 / 语速**：本机是 Kokoro 的中文音色 100 个（v1.1-zh，55 女 + 45 男，默认
  `zf_001`），千问是 48 个系统音色；两套偏好分开存，在**设置 → 悬浮球语音**里挑，
  旁边有试听，同一页还管朗读开关、语速和模型下载。这一页是插件用 `app.entry` / `app.page`
  插槽自己加的，没改宿主的设置页。挑完写本机，下一句就照新的念。
- **唤醒词**：打开「说『你好索罗』叫醒」后，面板关着时球会常听一小段 16 kHz 音频，
  命中「你好索罗 / 你好助理 / 小索」就开面板并自动开始录音。关键词在本机识别
  （sherpa-onnx `KeywordSpotter`，模型约 5 MB），关掉开关就不开麦克风；开不成时
  鼠标停在球上会说明原因（模型没下 / 麦克风没权限 / 浏览器不让后台听）。
  **模型只认中文拼音**：喊英文「Solo」识别不到，界面上一律写中文的「你好索罗」。
- **模型**：约 346 MB，第一次用时从 `hf-mirror.com`（失败退 `huggingface.co`）下到
  `<appRoot>/voice/tts/kokoro-zh`，文件钉死 revision 与 sha256；面板里有一行「语音模型还没
  下载（约 346 MB）· 下载」，带进度。没下的时候不出声，也不影响录音与转写。
  模型是 Apache-2.0（可商用）；不用 Matcha 的中文模型，是因为它训练自 Baker 数据集，
  仅限非商业用途。
- **本机优先**：转写用 macOS 26 自带的端侧模型（`SpeechAnalyzer`，源码是 `asr.swift`），
  录音不出本机、不留存档；朗读默认也是本地的 Kokoro（sherpa-onnx，模型文件在本机），
  不需要 API Key。只有自己把播报切到「千问云端」时，要念的文字才会发给阿里云 ——
  这时代码只收 `response.audio.delta` 的 PCM，不落文字记录。
- 后端路由：`POST /api/orb/transcribe`（`{ audio: base64, mime, lang }` → `{ text }`
  或 `{ error }`），它把录音落成临时文件、交给转写器，拿到文字后立刻删掉临时文件，
  同一时刻只转一段，后来的排队；`GET / POST /api/orb/voice`（在不在 / 开始下载 / 进度）；
  `POST /api/orb/speak`（`{ text, speed, sid }` → `{ wav }`，base64 的 WAV；模型没下时回
  `{ error, needModel: true }`）；`GET / POST /api/orb/speech`（播报引擎 / 千问 Key 在不在 /
  千问音色与语速，POST 保存）；`GET / POST /api/orb/wake`（唤醒模型在不在 / 开始下载 / 进度）；
  `POST /api/orb/kws`（`{ samples: base64 的 Float32, reset? }` → `{ hit, keyword? }`）。
  合成与关键词识别都串行。

**要求**：macOS 26 或更新；第一次转写要有 Xcode 命令行工具（`xcode-select --install`，
用来把 `asr.swift` 编到临时目录），系统会下载一次对应语言的语音模型。录音不走
`MediaRecorder`（Chromium 只肯录 webm，macOS 自带的 `afconvert` 打不开），前端直接收
WebAudio 的 PCM、封成 16 kHz 单声道 WAV 再发，后端只用 `afconvert` 做一次规范化 ——
不需要 `ffmpeg`。麦克风权限在系统设置里给 Solo。

## 不做什么

参考的是 [dsh-orb-cordis](https://github.com/mini-yifan/dsh-orb-cordis) 的**交互**，
不搬它的形态：

- **没有第二个 Electron 进程**，也没有自己的 userData —— 桌面壳里是同一应用的第二扇透明窗
  （ADR-116），浏览器里球长在 Solo 页面里；
- **没有 Computer Use**、不截屏、不点别的窗口：Solo 的权限边界是频道与工作区，
  插件不该绕过它；
- **不做第二套会话**：历史、已读、模型都跟着助理私聊走，没有本地账本；
- **不常开麦克风**：唤醒词是可选开关，默认关；关着就点一下才听。

关掉它：`enabled: false`。
