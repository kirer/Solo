# 代码流程图（code-flowmap）

把仓库里**所有代码**（`src/core`、`ui/app/src`、`desktop/src`、`scripts`、`seed/plugins`、`test`）
变成一张可滚动的左→右流程图。产物是一个 HTML 文件，不依赖服务、不联网、双击可看。

默认是**流程**视图：从真实入口出发的调用树（`FLOWS` 里 11 条：启动、装配、HTTP、我发一条消息、
写一条 + 叫醒、叫醒一个人、投递、say、团队沉淀、界面启动、桌面启动）。点顶部流程签切换；
每一步带「第几步 / 发生条件 / 文件行号」。切到**结构**视图就是完整的模块 → 文件 → 声明树。

## 一条命令

```bash
node .claude/skills/code-flowmap/flowmap.mjs
```

输出：仓库根 `code-flow.html`（已 gitignore）。生成器会：

1. 用 TypeScript 编译器 API 解析每个 `.ts/.tsx/.js/.mjs`；
2. 抽 文件 → 顶层函数 / 类 / 常量对象 → 类方法 / 对象方法；
   再从每个函数的 AST 里抽**调用点**（含 `if / else / switch / try / catch / 三元` 条件），
   按 `FLOWS` 的入口递归展开成调用树（深度 ≤7、节点 ≤700，超出会标省略）；
3. 摘要优先取 JSDoc / 行注释，文件级优先取 `docs/CODE.md` 的文件表（一份事实一个家）；
4. 读当前 `git rev-parse HEAD` 写进 `<meta name="flowmap-pin">`，并默认与**上一次生成时**的
   pin 做 diff，给节点打「新增 / 改动」标，页头显示变化数。

## 常用参数

```bash
node .claude/skills/code-flowmap/flowmap.mjs --stats          # 只打印文件/声明/方法数，不写文件
node .claude/skills/code-flowmap/flowmap.mjs --base <sha>     # 固定基线：标出该 commit 以来的变化
node .claude/skills/code-flowmap/flowmap.mjs --no-diff        # 不做 git 对比
node .claude/skills/code-flowmap/flowmap.mjs --out /tmp/x.html
```

**增量更新语义**：每次生成把当时的 HEAD 钉进 HTML。下次（有新提交后）直接重跑，
基线自动取旧 HTML 里的 pin，所以「改了什么」是相对**上次出图**，不是相对某个远古 commit。
想固定一条基线就用 `--base`。

## 为什么线不会交叉

布局是**左→右的 tidy tree**（Reingold–Tilford 的横向版），不是力导向，也不是自动布线：

- 每棵子树占一条**连续、互不重叠的纵向带**；父节点在自己的带内，孩子按阅读顺序自上而下排。
- 连线走正交折线：父右侧 → 竖直干线 → 每个孩子的左侧，全部落在**两列之间的专属走廊**里。
- 因为兄弟子树的纵带不相交，不同父节点的干线/支线在 y 上也不相交 → **零交叉**。
  这是构造保证，不是「看起来差不多」；`template.html` 里 `band()/place()/drawEdges()` 就是全部。
- 跨文件依赖**不画线**（任意 DAG 画在平面上必然交叉），放在卡片详情里当可点标签；
  点一下会滚到目标文件并闪烁。这样「树线」永远干净，「依赖网」靠交互查。

生成后可以在浏览器里机械验证：节点两两不重叠；所有 SVG 线段两两不相交（见下面的验收）。

## 流程视图怎么读、边界在哪

- 树根是一条流程的入口（`FLOWS` 里的 `file + name`；没有 `name` 就是文件顶层执行）。
- 每个节点是**一次调用**：`第 N 步` 是它在父函数里的调用顺序；橙色小签是**静态**条件
  （`当 …` / `否则` / `case …` / `出错时` / `收尾`），不是运行时真值。
- **虚框 + 「外部」**：调用名解析不到源码（`deps.foo` 这类注入依赖、Node/第三方模块）。
  如实留成叶子，不猜、不连假线。
- **紫色「回环」**：这个函数已在祖先链上出现（递归或互相调用），到此为止，避免无限展开。
- 只收**调用**，不画纯赋值 / return 语句；控制流靠条件签表达。同一函数里的重复调用去重。
- 跳转：流程步骤详情里的「位置」标签可点，会切到结构视图并定位到该文件；结构视图文件卡片
  的「依赖 / 被依赖」标签同理，点了滚到目标文件并闪烁。

## 界面约定

- 卡片结构固定：**中文短释在上 → 名字在下 → 「详情 ＋」在底**。点「详情」原地展开
  （签名、全文注释、行号、调用了谁、类型、依赖/被依赖、测试用例），再点收起。
- 顶部：**流程 / 结构**切换、搜索（`/` 聚焦，回车跳到第一个命中）、仅文件（只在结构视图可用）、
  缩放、图例（流程视图是流程签 + 步数；结构视图是模块签，第一次点跳过去、第二次点隐藏）、
  diff 徽标。缩放除了按钮，还支持 **Ctrl / ⌘ + 滚轮**（以光标为中心，范围 30%–250%）；
  **按住图上拖动可平移**（按钮/链接除外），右下角说明面板本身也能拖。
- 颜色按模块（流程签统一用强调色）；连线颜色取子树所属模块。
- **深 / 浅色主题**：右上角 ☾ / ☀ 切换；首屏跟随系统 `prefers-color-scheme`，手动切过就记在
  `localStorage["flowmap-theme"]`。所有颜色走 `:root` / `:root[data-theme="dark"]` 的 CSS 变量；
  深色下模块色会朝白色混 40%，保证边框、图例和连线不发闷。新增颜色时不要写死，先加变量。
- 左下角列出本次删掉的项；右下角是连线规则的说明（可关）。

## 数据与改哪里

| 想改 | 动这里 |
| --- | --- |
| 加/删模块分组、改顺序、配色、模块说明 | `flowmap.mjs` 的 `GROUPS` 与 `FILE_ORDER` |
| 加/改一条流程入口、流程说明 | `flowmap.mjs` 的 `FLOWS`（`file` + 可选 `name`；没有 `name` = 文件顶层执行） |
| 流程展开的深度 / 节点上限 | `flowmap.mjs` 的 `MAX_FLOW_DEPTH` / `MAX_FLOW_NODES` |
| 调用的解析规则（`this.x` / 命名空间导入 / 重导出 / 本地对象方法） | `flowmap.mjs` 的 `resolveCallee()` / `collectSites()` |
| 文件级中文摘要 | 优先改 `docs/CODE.md` 的文件表（生成器直接读）；没有表项才回退到文件头注释 |
| 类/函数/方法的中文短释 | 改源码里的 JSDoc / 行注释（生成器只认注释，不猜语义） |
| 卡片长什么样、交互、布局 | `template.html`（CSS + 渲染/布局/搜索/diff 展示） |
| 抽取规则（新的声明形态、用例名） | `flowmap.mjs` 的 `analyzeFile()` |

注意：

- **不写进 HTML 的假数据**：没有注释就如实显示「（源码无注释）」+ 签名派生的一句话，
  不编业务含义。
- 摘要只取注释第一句（≤72 字）；全文留在详情里。
- `docs/CODE.md` 的行号会漂，生成器不依赖行号，只按路径匹配。
- 新增一个源码目录时，把它加进 `GROUPS`（`dirs` 或 `files`），否则不会被收进图。

## 验收（每次改完生成器都跑）

```bash
node .claude/skills/code-flowmap/flowmap.mjs --stats
node .claude/skills/code-flowmap/flowmap.mjs
```

然后在浏览器里：

1. 控制台无报错；流程视图默认打开，「流程签」数量 = 生成器打印的流程数，`.node` 数量 = 该流程步数 + 1；
   切到结构视图后 `.node` 数量 = 统计里的 文件 + 声明 + 方法 + 模块 + 1；
2. 两种视图都：节点两两不重叠；
3. 两种视图都：所有 `#edge-g path` 的线段两两不相交（正交线段检查：横线 y 穿过竖线 x 且都在内部才算交叉）；
4. 点开任意卡片详情能展开/收起；搜索只搜当前视图、回车能跳；流程签切换会重排；
   结构视图的模块图例能跳转与隐藏，文件详情里的「依赖 / 被依赖」标签能切到目标文件；
5. 深浅色各看一遍：正文、路径、条件签、代码签名块、虚框「外部」卡都清楚可读，刷新后主题保持；
6. 换一个 `--base` 能看到 diff 徽标和节点上的「新增/改动」。
