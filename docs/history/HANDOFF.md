## 这一轮修掉的 11 个真 bug

按危害排序。**每个都是「测试全绿但实际不能用」的类型**。

| # | Bug | 后果 | 根因 |
|---|---|---|---|
| 1 | 员工能力包重名 | 所有员工共用一个名字，后招的覆盖前面的 → 部分员工**没有任何工具** | 底层按名字解析能力包 |
| 2 | 标识生成不支持中文 | CTO 派活全失败：`无法从"林越"生成标识片段` | `slug()` 只允许 ASCII |
| 3 | 生产清单混入测试模型 | CHRO 挑中 `faux-1`（零成本）→ 员工报 `no_model` | `DEFAULT_MODEL_CATALOG` 里有假模型 |
| 4 | 重启后角色失能 | registry 是内存态，幂等分支早退跳过了注册 → 所有岗位无工具 | 注册顺序错误 |
| 5 | CEO 拿到全部工具 | 不指定能力包 → 底层默认选全部 → CEO 能自己招人 | 违反 ADR-009 |
| 6 | `escalate`/`decide` 是空壳 | 装了工具但依赖没注入 → 上报静默丢失 | bootstrap 漏注入 |
| 7 | 输出截断被当成完成 | 模型输出 16k 上限被切断，`write` 参数没生成，却宣称「已交付」 | `maxTokens` 填太小（实际支持 200k） |
| 8 | 三栏画面错位 | `pi-tui` 的 `Text` 会强制折行，把排版好的画面重排 | 用了会「自作聪明」的组件 |
| 9 | 项目卡高度跳变 | 背面比正面高，没翻转的卡也被撑高 | 正反面绝对定位，容器高度塌成 0 |
| 10 | 服务 URL 端口错误 | 用 `port: 0` 让系统分配后，返回的地址仍是 0 | 没读 `server.address()` |
| 11 | 项目名与负责人混淆 | 项目卡显示项目名当负责人，看不出「谁在负责」 | 项目缺 `leaderName` 字段 |

**第 7 个最隐蔽**：第一次跑真实流程，开发说「已交付 1432 行游戏」，我去看目录——只有 PROJECT.md。后来才从 `stopReason: "length"` 发现它思考链吃光了 16k 预算，`write` 的工具参数根本没生成。

## 系统现在真实的能力边界

### 能做的（已验证）

- 老板 → CEO → 七个高管 → 项目 → 员工，全链路真实模型驱动
- CPO 自己立项建目录、CHRO 自己按 slug 配人（还会给员工起中文名）
- 员工按角色拿不同工具：开发能 `bash`、产品只能读写、运营只读
- 升级链：员工 → CTO → CEO → 你，你不在线也不丢
- 进程重启后状态完整保留（实测：关掉重开，CEO 还记得公司名）
- 崩溃自愈、受阻任务巡检、终端信号恢复
- 界面：三栏布局、流式输出、工具折叠、翻页、分支、拍板、重试

### 还不能做的（有意留白）

| 缺口 | 影响 | 为什么没做 |
|---|---|---|
| **流程编排靠提示词** | 依赖顺序（先立项再招人）靠模型遵守约定，偶尔会乱序 | 彻底解法要工作流引擎，超出 v1 范围（ADR-017） |
| 成本硬预算 | 只能看不能拦 | 底层 `beforeRequest` 无法拒绝请求 |
| 会议机制 | 员工不会自己定期开会 | v1 范围外 |
| 多项目并发 | 单进程单库，同时跑两个会冲突 | 底层无跨进程锁 |
| 会话删除 | 只能软删标记 | 底层无删除 API |
