# 架构决策记录（ADR）

记录**不可轻易更改**的工程约定。要改一条，追加新条目说明为什么，不要直接改旧条目；
觉得旧条错了，就新增一条「取代 ADR-0xx」。

> **编号从 ADR-001 重新开始（2026-10-31）。**
> 之前的 101 条记录已删除 —— 需要溯源时看 git 历史（`git log -- docs/DECISIONS.md`）。
> 导航文档（`AGENTS.md`、`docs/*.md`）里的引用已一并清掉；代码注释与测试里残留的
> `ADR-0xx` 是那个时期的标记，**不再指向当前任何条目**，判断行为以代码、`docs/` 正文与
> `seed/` 内容为准。下一条新决策才叫 ADR-001。

---

## 怎么写一条

一条决策只回答一个问题：**为什么这件事不能轻易改**。

固定五段：

- **背景**：之前的做法是什么，哪里不行（最好带上实测数字或踩过的症状）。
- **决策**：现在只有哪一种做法。
- **执行**：哪条测试 / 哪个检查守着它（没有就写「无」）。
- **取舍**：放弃了什么，为什么值得。
- **验收**：改完之后跑什么、看什么。

不写施工流水与文件清单（那些在 `docs/CODE.md`），也不写「以后可能怎样」的猜测。

## ADR-001 轨迹从会话条目派生，不落库

- **背景**：V3 把 `think` / `tool` / `work` 的过程投影从频道里删掉了 —— 它们混在人的对话里，
  机器留痕被读成「他说了这句话」。删干净之后，agent 干活的几分钟界面上是静的：
  跑了什么命令、改了哪个文件、为什么失败，只能事后翻日志。CONCESSIONS C-007 也记过：
  草稿和 token 流都不可靠，删了。
- **决策**：轨迹**只读派生**，不新增表、不写频道、不发草稿。一轮 = 会话里那条
  `kind: "core.channel"`（`data` 带 `channelId` / `seq`）到下一条 `core.channel` 之间的全部条目；
  助手消息里的 `thinking` / `text` / `toolCall` 与工具结果本来就在会话里。
  新接口 `GET /api/channels/:id/trace` 读它，SSE `trace` 只推节流后的快照。
- **执行**：切轮与摘要写成纯函数（服务端切轮、前端排版，同一套判据各一份），单测守
  「摘要文案、连续 think 合并、`[PASS]` 不画、截断」；`check-boundaries.mjs` 要求新路由
  在前端有消费者。
- **取舍**：读一次要扫会话条目（单轮上限 200 步、64 KB）；进程重启或会话回收后，历史轨迹
  可能读不到（返回 `null`，界面不画）。换来的是频道里永远只有人说的话 —— 机器做过什么，
  在另一个维度里看。
- **验收**：真模型跑一轮，轨迹里的命令/文件与频道里的结论对得上；刷新后同一条轨迹仍在；
  `workspace/core.sqlite` 不因轨迹变大。

## ADR-002 前端保持 React 18 + Vite，桌面端后置成壳

- **背景**：参考实现（deepseek-harness）是 `apps/web`（Vite + React）+ `apps/desktop`（Electron 壳），
  客户端逻辑收在共享的 client 层。我们已经有 React 18 + Vite + 手写 CSS，换栈的收益为零。
- **决策**：不换框架、不引组件库、不引 Tailwind。平台差异只经过 `ui/app/src/platform.ts`
  （storage / openExternal / copy）。桌面端以后用 Electron 加载同一个本地服务，不重写界面。
- **执行**：不引平台抽象层（一开始写的 `platform.ts` 没落地 —— 为两个调用写一层壳，
  比直接调更绕）。`localStorage` 只出现在 `state/store.ts`（界面开关与轨迹展开状态），
  剪贴板走 `lib/format.ts` 的 `copyText`；这两处是以后套壳时唯一要看的文件。
- **取舍**：放弃「一次做成跨端组件库」；换来改造面小、样式完全可控、六档字号不被工具类打散。
- **验收**：`grep -r "localStorage" ui/app/src` 只命中 `state/store.ts` 与 `stream/RunBlock.tsx`；
  `npm run ui:build` 的产物能被 Electron 直接加载。

## ADR-003 轨迹接口拆成「窗口摘要」与「单轮全文」

- **背景**：ADR-001 写的是 `GET /api/channels/:id/trace?seq=`，一次返回一轮的完整步骤。
  实现时发现两个问题：① 一条消息可以叫醒多个人，`seq` 不唯一；② 消息流首屏有十几轮，
  每轮八步，全带会把一次读放大到几百 KB。
- **决策**：拆成两条 —— `GET /api/channels/:id/turns?from&to` 返回窗口内每一轮的**折叠版**
  （`stepCount` + `summary`，不带 `steps`）；`GET /api/channels/:id/turn?seq&slug` 返回
  一轮的完整步骤。SSE `trace` 推正在跑的那几轮的瘦身版（每步输出 ≤ 2 KB）。
  这是 ADR-001 的接口细化，**不改变「不落库」那条**。
- **取舍**：折叠态与展开态是两种形状，前端要认 `steps === undefined` 是「还没拉」而不是
  「没有过程」；换来首屏读小、展开只拉一次。
- **验收**：`npm test` 的 `test/core/trace.test.ts`；真模型跑一轮时，折叠行有摘要、点开有步骤。

## ADR-004 每个成员一条私聊；过程在私聊里看，群聊只留结论

- **背景**：ADR-001 把轨迹派生出来之后，轨迹块挂在**群聊消息下面**。真跑起来的结果是
  群聊被过程淹了：一个团队频道里连着几十条「在想 / 跑了 N 条命令」，人说的话要找半天。
  同时私聊是「我开的时候才存在」的（`ensureDm` 明确不存在），所以 agent 的工作过程没有
  一个属于「他」的地方 —— 它属于**频道**，不属于人。
- **决策**：装配 / 招人时给每个成员幂等地建一条 `dm:<我, 他>`（`ensureOwnerDm`）；
  群聊**不再画轨迹块**；私聊是工作记录页，按时间合排「私聊消息 + 这个人在所有频道里的轮次」
  （`GET /api/people/:slug/turns`，SSE 在私聊里推他的跨频道轮次）。
  私聊仍然是两个人的房间：agent 不能私下找另一个人，也没有「个人频道」。
- **执行**：`test/core/assemble.test.ts` 守「新人一出现就有私聊」；`test/ui/stream-model.test.ts`
  守群聊不画轨迹、工作行按时间插、跨频道键不撞；`scripts/core-live.ts` 的「新人」阶段
  检查私聊成员恰为 `{owner, 他}`。
- **取舍**：侧栏频道数随人数线性增长；每个成员多一条空频道。换来的是「这个人干了什么」
  只有一个入口，群聊回到对话本身。
- **验收**：真模型跑一轮团队任务，团队频道只有结论；点开那个人的私聊能看到他在团队频道里
  的那几轮；`npm run live` 两次 16/16。

## ADR-005 团队管理员必须是名册里的真实成员，写 README 时拒绝

- **背景**：建团队时助理直接把自己写进 `lead`，团队频道于是把助理当管理员：他既是统筹者，
  又是被叫醒干活的人，派活与验收混成一个人。技能里写了「不能是你自己」，但技能是建议，
  模型照样写过。
- **决策**：`file` 写 `teams/<slug>/README.md` 之前校验 `lead`（`team/doc.ts` 的
  `leadProblem`）：必须有；必须是 `agents/` 里真实存在的 slug；不能是直接向 owner 汇报的
  助理。不通过直接拒绝、不落盘、不 `syncTeam`，错误文案告诉模型「先招一个团队管理员」。
  流程本身写进技能「建立团队」：第 1 步招人，第 2 步写 README。
- **执行**：`test/core/team.test.ts` 守三条判据；`test/core/tools-actions.test.ts` 守
  「拒绝时不落盘」「合法 lead 照常写」；`scripts/scenario-live.ts` 的 `build-team` 场景
  检查 `lead` 在名册里且不是助理。
- **取舍**：合法的「助理兼管理员」配置被禁掉了；老工作区里没有 `lead` 的 README 下一次
  被 `file` 写入会失败。换来的是团队频道「谁负责」这件事不再靠模型自觉。
- **验收**：让助理建团队，它先 `hire` 一个管理员再写 README；直接写 `lead: 自己` 被拒绝。

## ADR-006 说话不进过程：`say` 不画成步骤

- **背景**：工作记录里的步骤树把 `say` 也画成了一行（「说了一句」/「在 #小恐龙 说了一句」），
  点开是那句话的原文。可那句话本身就是频道里的消息，私聊里就排在这块工作记录旁边 ——
  同一段话出现两遍，而且「说出来」被算进了「做了几步」。
- **决策**：`buildTurn` 不再把 `say`（工具调用或纯正文）收进 `steps`；`stepCount` 与摘要
  随之只数「做的事」。只说了话、没做事的一轮不画 work 壳（`buildWorkRows` 跳过
  `stepCount === 0`）。话在它落到的那个频道里看；工作记录只答「他做了什么」。
- **执行**：`test/core/trace.test.ts` 守「say 与正文都不进步骤」；`test/ui/stream-model.test.ts`
  守「空轮不画壳」；`docs/WEB-API.md` 的 `ViewStep.kind` 去掉 `say`。
- **取舍**：私聊的工作记录里不再显示「他在别的频道说了什么」，要去那个频道看。
  换来的是「消息」和「过程」两种东西彻底分开，不再重复。
- **验收**：真模型跑一轮，私聊里一句话只有一条消息气泡，工作记录里只有思考与工具调用。

## ADR-007 头像换成服务端画好的插画（DiceBear `micah`）

- **背景**：原来的头像是前端手绘的几何脸 —— 三族外形 × 六色底，两种眼睛。它能稳定区分
  「谁是谁」，但一屏排下来全是同一个意思：一个身体加两个点。中文名首字区分度本来就低
  （「林越」「林墨」都是「林」），读人只能靠旁边的名字。
- **决策**：头像改由服务端生成插画（`@dicebear/core` + `@dicebear/collection` 的 `micah`），
  `GET /api/avatar/:seed?size=` 直接吐 SVG；前端只拼 `<img class="av" src="…">`（
  `ui/app/src/lib/avatar.ts`）。种子是 **slug**，取景固定（`scale 170` / `translateY 18`），
  底色 6 支淡彩按 slug 挑；同一张脸永远同一张，长缓存一周。
- **执行**：`src/core/app/avatar.ts` 是唯一的画法（纯函数）；路由在
  `interface/http/routes.ts`；`test/core/avatar.test.ts` 守「同 seed 同字节」「尺寸夹在 16–256」
  「ETag 跟着 seed 与尺寸变」。
- **取舍**：多了一个依赖（约 1 MB 的图形数据，只装在服务端，不进 bundle）；头像从「一行
  内联 SVG」变成「一次 HTTP 请求」（`<img>` 有浏览器缓存，一屏几十张也只是一批）。
  换来的是扫视时真的能认人 —— 发型、肤色、表情、眼镜都在变。
- **已知代价**：插画是 `<img>`，CSS 进不去内部结构，所以「眨眼」这个动效没了，三态改成
  整张脸的歪头 / 点头 / 回弹（§6.5、§6.4）。画风如果要换，老缓存最多留一周（`max-age` 不是
  `immutable`）。

## ADR-008 删掉输入卡上方的活动条

- **背景**：私聊里输入卡上方有一条 32px 的活动条（「● 苏禾 在做活 10s ›」），每轮开跑时
  从 0 高度展开、跑完收起。可它显示的是**过程**，而过程已经在私聊的工作记录里一行一行
  排着了；一条跟着每一轮冒出又消失的横条，正好落在最需要安静打字的输入区上方。
  群聊那条在 3606b48 已经去掉，私聊这条一直留着。
- **决策**：`ui/app/src/composer/ActivityBar.tsx` 连同渲染与样式一起删掉；`store` 的
  `activity` 映射也删掉（头像的忙态仍由 `presence` 从 `/api/org` 的 `people[].activity`
  派生，接口字段不动）。
- **取舍**：想知道某人在跑什么，要去私聊的工作记录里看那一轮（他开跑时那一块本来就会
  长出来）。不再有「一眼看到他此刻在跑什么」的入口。
- **验收**：私聊输入卡上方不再出现任何运动中的东西；`/api/org` 的 `activity` 仍然驱动
  头像的 working 态。

## ADR-009 「需要你」只认显式 @我；团队指令必须发在团队频道

- **背景**：一次真实运行里，知言私聊 43 条消息中有 13 条被标成「需要你」。拆开看，6 条是
  它把本该发给团队的指令写进了和我的私聊（正文 @ 的是沈舟、林越，可他们不在这个私聊里），
  团队频道查不到这几条；另外 7 条里只有约 4 条真在等我回话。放大噪音的是旧规则：
  `kind=decision` 且「没明确点本频道成员」时自动把我补进收件人 —— 助理几乎每条公告都打
  decision，而它在私聊里 @ 的团队成员都不是私聊成员，「没点别人」必然成立。
- **决策**：两处一起改。① `say` 只在**正文显式 @我**时把 `owner` 加进 `mentions`；
  `decision` 标签只是分类，不再替我找人。② 私聊的投递附言从「只回这里，别去群里说」
  改成「回答我只回这里；要指挥团队，就回团队频道说一句」——旧文案正是在教它把全团队的
  指令压在私聊里。
- **取舍**：助理拍板后要我看，必须自己写 `@我`，不然这条不会进「找你」。这个代价换掉的
  是：每条通告都变成待办，真正的提问被 13 条噪音埋住。技能「工作规矩」里那条
  「带 decision 标签、又没点别人时系统会把我算进收件人」同步改掉。
- **验收**：`say-contract.test.ts` 守「decision 不补 owner」「私聊附言指向团队频道」；
  真跑一轮：助理在私聊里汇报、在团队频道里派活，私聊里只有显式 @我 的消息挂「需要你」。

## ADR-010 审计走 pi-durable 的钩子，只读不改

- **背景**：排查「他为什么忽然不说话 / 这一轮为什么这么慢」时，手里只有频道消息和
  `logs/runtime.jsonl`（底座报错）。**工具调用、耗时、token、模型停止原因**一个都没有 ——
  C-009 记的就是这件事。而底座 1.4 的扩展本来就有 `hooks` 字段（`hook(ToolTask, …)` /
  `hook(GenerationTask, …)`），我们一个都没装过（`grep hook(` 零命中）：`core-tools` 只带了
  `tools`，身份扩展只带了 `sections`。
- **决策**：新增 `app/audit.ts`，两个钩子挂在 `core-tools` 扩展上（它是每个会话都选的扩展，
  装一次 = 全都在审）：
  - `beforeTool` / `afterTool` → 一行：谁、哪个工具、成没成、耗时；
  - `afterResponse` → 一行：谁、模型、停止原因、耗时、输入 / 输出 / 缓存 token、成本。

  落 `workspace/logs/tools.jsonl`，5MB 轮转一代（与 `jank.jsonl` / `runtime.jsonl` 同一套
  `appendJsonLine`）。钩子**只读不改**：不改参数、不拦调用、不改结果；写失败就丢这一行。
- **为什么不是写在工具里**：工具只看得见自己跑成功的那一次。失败的、被拦下的、底座自己
  生成的错误结果，工具里一个字都留不下 —— 而那正是要查的时候。
- **为什么不做另外三件事**：
  - **拦截**（密钥 / 路径越界 / 建团队权限）留在工具里：那里有 `workspaceRoot` 和名册，
    `HookApi` 拿不到，硬搬过去等于把校验拆成两处。
  - **自动重试**：`beforeTool` 在调用之前，重试不了；`afterTool` 只能替换结果，替换出来的
    还是同一次执行。要重试得在工具内部做。
  - **超时看门狗**：钩子没有「请求进行中」的时刻可以等，超时归底座的重试策略。
- **取舍**：每次调用 / 每次回复多一次 `appendFile`（不 await，失败丢弃）；日志会一直长，
  靠 5MB 轮转封顶。审计只在本机、只给排障看，**不进任何接口**。
- **验收**：`test/core/audit.test.ts` 钉行的形状（谁 / 工具 / ok / ms；没走过 `beforeTool`
  就不写 `ms`、认不出人就不写 `who`）；真跑一轮看 `logs/tools.jsonl` 里 `tool` 与 `model`
  两类行都在。

## ADR-011 `say` 的 channel 认频道名，不认就落回私聊

- **背景**：真实运行里，知言在私聊里被我叫醒，想给团队派活，写下「@温言 用户在 Wechat-B 上
  已经扫码登录成功…」。这条落在**私聊**：团队频道 88 条消息里它只发过 2 条，而私聊 60 条里
  它发了 40 条；它还回我「团队那边已经收到并指派了温言」，因为 `say` 确实返回了「已发到
  「知言」#55」。根因不是它不肯发，是**手上没有可写的东西**：提示词里只给频道标题
  （`群「QQ农场」`），`say.channel` 要的却是 `team:qq-farm`。省略 channel 就落回唤醒频道，
  也就是私聊。投递附言写了「在这里说的话只有我看得见」，它照发 —— 文案治不了这个。
- **决策**：`defaultChannel` 的显式频道先按 id 找，找不到再按**标题全等**在「我所在的频道」
  里找；重名直接报错并列 id；都没有就报错并列出我在的频道（id + 标题）。提示词只动两处：
  `80-reply.md` 的「频道参数省略即可」加三个字变成「**回话时**省略频道参数即可」；
  `84-dm.md` 的「回团队频道说一句」改成「用 `say` 把 `channel` 写成那个团队频道的名字」。
  换频道这件事**只在私聊那一句里说**，不进通用回话规则（见下）。
- **为什么不是硬拦**：最早想的是「正文 @ 了不在本频道的人就拒绝」。那治的是「没做到」，
  但这次是「做不到」—— 它想发，没地方发。先补能力，再谈纪律。
- **为什么不做模糊匹配**：`mentions.ts` 早就定过这条（别名只认精确匹配，拼音 / 职位 /
  `@老板` 一律丢弃）。频道名同理：只认标题全等，且只在我自己的频道里找；重名报错让人选，
  不猜。
- **取舍**：频道标题不是唯一键，两个团队同名时必须写 id（错误信息里给了）。工具参数说明
  从「频道 id」变成「频道 id 或频道名」，多一个概念，但换来「回团队频道说一句」第一次
  成为一句能执行的话。
- **踩过的坑（同一次改动里）**：第一版把「要发到**别的**频道，把名字写进 `channel`」写进了
  通用的 `80-reply.md`。真跑一遍掉到 13/16：成员乙被我在全员频道叫醒，除了照规矩报给团队
  管理员，还额外往全员频道贴了一条「@我 这个我定不了」—— 那句话被当成通用建议，鼓励它
  往别的频道多贴一份。改成只在私聊附言里说换频道，连跑两次 16/16。通用回话规则里
  **不要**出现「别的频道」这种话。
- **验收**：`say-contract.test.ts` 守三件事 —— 有唤醒记录在私聊时，写频道名照样落到团队
  频道；重名报错且不落盘；名字写错时把「你在：…」连 id 一起给出来。

## ADR-012 技能加一层「团队」：`teams/<团队>/skills/`

- **背景**：技能原来只有全员层（`skills/`）和个人层（`agents/<slug>/skills/`）。团队频道
  的技能栏因此是空态，界面上写着「团队没有技能目录」。可事实是团队确实会攒自己的做法
  （这个团队的发布流程、这个客户的验收口径），写在 README 里既不像手艺也不进提示词的
  技能段，成员根本读不到。
- **决策**：加第三层 `teams/<团队>/skills/<名字>/SKILL.md`，`SkillScope = "all" | "team" |
  "personal"`。合并方向是**下层覆盖上层**：全员 → 团队 → 个人，一个人看到的是三层并集，
  同名只留最靠下的那份，提示词里标「全员通用 / 团队共用 / 你自己写的」，被盖住的那份带
  `overrides`。
- **为什么是团队而不是「每个频道」**：团队是磁盘上的一个文件夹，也是提示词里已经存在的
  边界（`30-team.md`）；频道是投影，私聊频道还会随人消失。把技能挂在团队上，技能的
  归属和「谁能看见」都跟组织一致。
- **为什么写入口还是 `file` 工具**：早先的 `skills(action=write)` 已经删了（它只是
  「往固定路径写 md」的包装）。团队技能就是一个文件路径，`file` 写
  `teams/<团队>/skills/<名字>/SKILL.md` 即可，不新开工具、不新开 `scope` 参数。
- **取舍**：一个人同时只在**一个**团队里（`identity.md` 的 `team` 只有一个值），所以
  「看得见哪一层的团队技能」不需要额外配置；哪天要跨团队共享，这里得再加一条规则。
  团队技能不进 `seed/`（出厂内容只有全员层），开团队时团队自己写。
- **验收**：`skills.test.ts` 的「技能：团队层」三条（团队内可见 / 覆盖方向 / 别队看不见）、
  `team-profile.test.ts` 的档案字段；界面在团队频道的「技能」栏列出这一层。

## ADR-013 后台命令：跑完自己回来

- **背景**：`run` 只有两条路。前台等它跑完（最长 300 秒），或者以 `&` / `nohup` 脱手
  （立即返回 PID，**永远没有回音**）。跑一次完整测试、一次构建、一段长脚本，前者会卡死
  一轮，后者等于把它扔进黑洞：跑完了没人知道，跑挂了更没人知道。
- **决策**：`run` 加 `background: true`。起跑时就把「结果回哪个频道」定下来（用
  `defaultChannel`，此刻的唤醒记录才对），立刻返回；跑完由 `channel/jobs.ts` 把结果作为
  一条 `note` 发回那个频道，并用 `wakeTo` 叫醒起跑的人。最多跑 30 分钟，到点整组杀掉。
  起跑前在 `logs/run/<id>.json` 留一条记录，跑完删掉；服务启动时 `app/runs.ts` 扫一遍，
  活着的杀掉、死掉的照实留一句。
- **为什么不用 `&` 代替**：这是两种意图。「起个服务，别管我」和「这条慢命令跑完告诉我」
  混成一个参数，前者就会在 30 分钟后被当成超时杀掉。
- **为什么结果从「我」发、而且是 `note`**：它是系统产出，不是哪个 agent 说的话；`note`
  不计未读、默认不叫醒任何人 —— 所以 `post.ts` 加了 `wakeTo`：显式给收件人时才叫醒。
  收件人是「谁起的这条命令」，不重新解析正文里的 `@`。
- **取舍**：结果只回起跑的那个频道，不广播；回给模型的只有输出尾巴（8000 字），全文在
  `logs/run/<id>.log` 里，路径写在消息里。进程崩了只能告诉你「它断了」，不会自动重跑 ——
  重跑是起跑那个人的决定。记录里只有 pid：pid 被系统复用时清扫会误杀一个无关进程
  （很少见）；要更稳得连进程启动时间一起记，现在没做。
- **验收**：`run-jobs.test.ts` 五条（跑完回调 / 超时杀掉 / 起不来也回话 / 重启清扫 /
  `note` 默认不叫醒、`wakeTo` 才叫醒）。

## ADR-014 群聊里的字数上限比私聊紧

- **背景**：一条 `say` 统一 1200 字。线上见过 21,568 字的一条 —— 那不是说话，是把整个
  思考过程倒进频道。可 1200 对群聊还是太宽：一群人都在看的频道，长段落没人读完。
- **决策**：群聊 600 字，私聊 1200 字（`guards.ts` 的 `sayLimitOf`）。超了不落库，回一句
  「太长了」并告诉它把过程写进团队文件、只发结论加路径。
- **取舍**：硬拦会让它重写一次（多花一轮）。但把 700 字的结论倒进群里，花的是所有人的
  注意力，而且没有人读。
- **验收**：`say-contract.test.ts` 的「群聊里的上限比私聊更紧」与「超长正文不落库」。
