## 0. 这一版解决什么

v3 把「像不像一个原生聊天应用」做对了，但它回答不了这个产品最核心的一个问题：
**agent 干活的两分钟里，屏幕上什么都没有。** 我看到的只有它最后说出口的那句话。

三个具体问题：

1. **过程不可见。** 它跑了 3 条命令、读了 5 个文件、写坏了 1 个文件 —— 我全都不知道。
   出了问题只能去翻 `<userRoot>/logs/` 和会话记录。Claude Code 的整个界面就是围着这件事
   设计的（图 1）：工具行折叠成一行、带耗时、点开才看细节。
2. **右栏只有一个维度。** 现在右栏只讲「这个频道/这个人是谁」。DSH（图 2）把右栏做成
   「对话 / 轨迹 / 上下文」三个视图，同一份数据换一个看法，不用离开这一屏。（v6 的
   答案是：右栏不切视图，一张表从上往下读，过程去后台任务那一态 —— §13.2 / §13.3。）
3. **状态是猜的。** `presence` 现在是「最后一条消息在 5 分钟内 → idle」这种启发式，
   不是真的忙闲。侧栏那个「在做」是假的。

**一条新的硬规矩：过程可见 ≠ 过程落库。**

轨迹**不写进频道、不进 SQLite、不发草稿**。它从底层会话条目现算：

- 每条投递都往会话里写一条 `kind: "core.channel"` 的条目，`data` 里带
  `{channelId, seq, from, text, mentions}`（`core/flow/runner.ts`）；
- 所以**一轮 = 从这条条目到下一条 `core.channel` 条目之间的全部条目**；
- 助手消息里有 `thinking` / `text` / `toolCall` 三种内容块，工具结果是一条
  `ToolResultMessage` —— 全部躺在会话里，读一次就有。

这条路径同时满足三件事：不加表、不改消息 schema、刷新之后轨迹还在（会话本来就在）。
CORE §12 说「以后用 `harness.inspect()` 派生，而不是把思考落库」——**这就是那件事的做法**。

**留下的三条（不许动）：**

1. **颜色只上数据，不上 chrome。** 一个强调色；没有彩色按钮、彩色胶囊、彩色图标底。
2. **正文 14/24，字号只有六档。** 层级靠留白和灰阶，不靠字号和加粗。
3. **不画后端没有的东西。** 每个 UI 元素都要在 §8 的数据来源表里指到具体字段；
   没有就写「🆕 需后端新增」，并且那一块在接口落地前不画。

- **（v4 记录，已作废 —— ADR-084）最左 78px 是应用级导航**（原 `sidebar/Rail.tsx`）：从上到下 **聊天 → 插件**，插件自己的

  它和侧栏那行标题是一条线，多一个标就把这条线断开。品牌在窗口图标与标题里。
  **一格只有一枚图标，不写字**（微信桌面版就是这样）：名字在 `data-tip` 里，悬停出头一条
  自绘提示（`shell.css` 的 `.rail-item::after`，不用 `title` —— 原生提示要等一秒）；
  78px 里塞不下四个汉字，挤成两行反而更难认。出厂「Token 统计」是 `rail.item` 的第一个
  消费者：点开是一整页用量面板。
  选中的那格是一块 `--active` 浅底。它和侧栏不是一回事：
  侧栏讲「这个组织里有谁、有哪些频道」，这一列讲「这个应用有几个地方可去」。
  **这一列只有两个去处**（§13.3）：聊天是主列，插件与设置是整屏的第二屏。
  都不盖一层抽屉。
  手机上这一列不再是底部一条：**入口在标题栏**（左上「对话」、右上「设置」，§13.7）。
- **侧栏 288px**，右侧 0.5px `--line`。**没有收起态**：以前那颗「收起侧栏」能把这一列
  压成 56px 的头像条，收起来之后名字、状态、预览全没了，只剩一列认不出的脸 ——
  切回来还得再点一次，省下的 232px 不值这个来回，按钮连同 `data-side` 那套规则一起删了。
  比 v3 的 260 宽 28px：
  行里要放 36px 头像 + 两行字，260 那一档名字稍长就被省略号吃掉。
- **顶栏 52px**，只在主列上方；侧栏自己的头上一行标题写「聊天」，不画 logo
  （两列的头连成一条线，见上一条）。
- **消息列宽** `min(100% - 40px, clamp(720px, 68%, 880px))`，居中。比 v3 的 680–920 略窄：
  轨迹块里有命令和 diff，行太长反而难读。
- **右栏 360px**（v6 稿子量的是 372，§13.7 —— 落地时按稿子一次改齐，别一半一半），
  默认收起。它是**布局的一部分**（展开时中列真的变窄），不是浮层 ——
  理由同 v3 §1.2：盖住的浮层在写长消息时是灾难。**≤1100px 时右栏让到 300px**：
  再宽，中列就一行放不下六个字了（笔记本分屏那档）。
- **两条边栏同底**：左栏与右栏都是 `--frame`，中间那张纸才是 `--ground`，卡片再用
  `--field`。右栏早期用 `--field`，深色下比左栏亮一档，看着像浮起来的另一块地方。
  深色下三栏都是近黑的一张纸（`--frame` `#0f0f0f`、`--ground` `#0a0a0a`），差一档就够，
  分隔主要靠 0.5px 的线；浅色仍是 DSH 那套 `#f9fafb` / `#fff`。
- **不用色彩分层。** 层次只靠 `--frame` ↔ `--ground` ↔ `--field` 三档灰 + 发丝线。
- **进来不替人选频道。** 中栏先站着落地页：一个标（56 的圆角方图，和空频道卡片的画法
  同源）、一句「挑一个会话」、一句提示。不塞卡片 —— 一张卡漂在大空地里读起来像加载失败；
  也不给「刷新」按钮 —— 列表由 SSE 自己更新，一个常驻的刷新键等于承认它会过期。
  顶栏这时只剩右上角一个「找助理」（点开和助理的私聊），`N 件找你` 与「详情」都收起：
  没有频道就没有详情，落地页也不该先塞一件要人处理的事 —— 未读仍然在左栏的徽章上。
  输入框一并收起：没有一个频道，就没有「发出去」这回事。手机上列表就是第一屏，
  落地页只在宽屏上出现，所以「找助理」在手机列表页没有入口（助理本来就是列表第一行）。

### 1.2 右栏：一张表，一个开关（v6 收掉了 tab 条，见 §13.2）

> v4 这里是「详情 / 技能 / 记忆 / 文件」四个 tab（下表留着是因为每个 tab 讲什么还成立）。
> v6 把四段收成一张平铺的表、顺序固定、不用切 —— 表在 §13.2，**以那一节为准**。
> 下面关于 tab 条、分段控件、tab 切换动画的句子，落地时一并删掉。

| 视图 | 讲什么 | 数据 |
|---|---|---|
| **详情** | 群聊：这个频道是谁、几个人、团队目标与现状，点成员钻进档案；私聊：直接是那个人的档案 | 现有 `/api/channels/:id`、`/api/people/:slug` |
| **技能** | 这个人的手艺：他会什么、哪些覆盖了全员同名 | 现有 `GET /api/people/:slug` 的 `skills[]` |
| **记忆** | 这个人的记忆全文，可删可加 | 现有 `/api/people/:slug/memory` |
| **文件** | 当前频道那个工作区的目录树 + 预览（插件，出厂「文件树」注册） | `GET /api/p/文件树/tree` / `GET /api/p/文件树/preview` |

**栏顶先是一张身份卡，三个 tab 挂在它下面**（v4 的排法：tab 原本在顶栏里，换 tab 时
那块「这是谁」跟着一起消失）。卡片是一块描边的浅面（同 `--frame` + 0.5px `--line`，16 圆角，四周留 16），居中排：头像 96、名字 22/700、身份徽章，加一行**只有后端真有的**
数字（私聊卡上的徽章写他本人的**职务**，不是「私聊」—— 卡片说的是这个人，不是这个频道） —— 人物页是「状态（在线表）/ 频道数」，团队频道是「成员数」。设计稿里还有
一列「~1.2s 响应」，后端没有这个字段，不画。只有一项时标签和值排在同一行，不做上下堆叠。

**群聊的详情只画这个频道的事实**：团队现状（`doing`）与成员列表（头像与名字、身份、
管理员都在卡片和网格里）。**不画「本窗口多少条消息」「最近一条」** —— 那是读取窗口的实现细节，
不是这个频道是什么。成员网格最后一格是**我**（看得见、点不动：我没有档案页），前面才是别人；
「成员 N」这个数就是格子的个数，两边必须对得上。

**成员四列网格**（稿子 08）：头像 52 在上、名字在下，一行四人；身份不画 —— 格子里只有
名字，身份点进去看。两列或一列会把四五个人拖成好几行，四列才是一眼扫完（窄到 375 仍然放得下）。

**团队频道多一段「团队介绍」**：`teams/<slug>/README.md` 的正文（目标 / 验收标准 /
不做什么 / 当前进展），和「预置提示词」同一个可滚的框。团队的事实都在那份文件里，
详情页不读它就等于只说了一半。

**私聊的详情就是那个人的档案**（和点成员进来看到的是同一块）：头像、名字、头衔、模型、
汇报给、在哪些频道、预置提示词。一对一里再列「成员 2 / 我 / 他」是把同一件事说三遍。

「模型」那一行在最上面，由插件画（`rightPanel.detail` 插槽，出厂「模型管理」注册）：一个
下拉，默认是「跟随默认（…）」，换一只就当场生效 —— 数据来自 `GET /api/people/:slug` 的
`model`、`GET /api/models` 的**现在生效**清单与 `POST /api/people/:slug/model`。只列真能用的：
`settings.json` 改过之后内核会就地重装注册表（ADR-025），所以刚加的模型就在下拉里，
不进下拉的只有「装了但装不上」的，下面写一句「还有 N 个没装上」。一个能用的都没有时不画空
下拉，而是分两种说清楚：文件里一个都没配，写「还没有配置模型」并指路设置 → 模型；文件里配了
却一个都没装上，写「配了 N 个，一个都没装上」并指路检查地址 / 协议 —— 后一种要是也说
「还没有配置模型」，人会被送去设置页白改一遍。他此刻用着的那只如果已经
不在清单里，会以「（已不存在）」列在最前面 —— 那是**真的**，不标出来他就静默 `no_model`。

**「文件」页签是插件画的**（`seed/plugins/文件树/`）：私聊看那个人的 `workspace/`，团队频道看
团队的 `workspace/`，全员频道没有工作区就不画这个页签。点开一个文件就地预览：图片 / markdown /
代码给文本，HTML 放进 `sandbox=""` 的 iframe（永远不执行脚本）。`rightPanel.tab` 只给文件树用 ——
插件清单在「设置 → 插件」里，页签不该只列一张清单。

**详情不重复技能与记忆**：那两样各有自己的 tab。人物档案里只留「汇报给 / 在哪些频道 /
预置提示词」。「活跃频道」是**两列网格**，每格一个**群组图标（按 `channel.members` 画真头像）+ 频道名**（名字长了单行省略）——
一行一个会把两三个频道拖成三行。**私聊不算活跃频道**：那是和他说话的地方，列出来会变成
「Solo的活跃频道里有Solo」。一个群频道都没有时整段不画。点一格切到那个频道。

**右栏没有「轨迹」这一栏。** 过程跟着人走：跑的时候是聊天流里的一条 `live` 占位，跑完进
这个人的后台任务（§2.3）—— 桌面上它是**这一栏的另一种状态**（右栏整块换成清单 + 一轮，
聊天不动），手机上它铺满整屏（`.detail` 本身就是整屏浮层）。它讲的是「这个人干了什么」，
所以内容按人排，不是按频道；入口有两条：聊天里的 `live` 行，和资料表最后一行「后台任务」。
**同一件事只有一个家，可以有两个门。**

右栏这一态与资料表不并存：进了任务态，栏顶换成「后台任务」+ 一个收起键；收起回到资料表，
滚动位置不重置。**已落地**（2026-11-06，ADR-083）。

- **技能与记忆按频道作用域取，不混着列**：私聊 / 人物页只讲这个人（`scope: personal`），
  团队频道只讲团队，全员频道只讲全员都会的。判据是频道自己：`kind === "dm"` 或个人页 →
  个人；群聊有 `team` → 团队；其余（全员）→ 全员。不另存一份「当前作用域」状态。
- 个人作用域里栏顶有一个人物切换（`Solo ▾`，列出频道成员）；**私聊里没有这一行** ——
  候选只有一个，名字和下拉都是废话，这一栏讲的就是对面那个人。
- **团队频道的「记忆」栏是团队记忆**（`teams/<slug>/memory.md`），只读：写入只有
  `remember(scope=team)`（成员或助理）与直接写文件。**团队频道的「技能」栏是团队层技能**
  （`teams/<slug>/skills/`，`SkillScope = "team"`）：这个团队的人打开提示词就能看见这份清单，
  空态是 `这个团队还没有自己的技能` + `团队技能放在 teams/<slug>/skills/ 下`。
- **全员频道**：技能栏只列 `scope: "all"` 的那一层；记忆栏是空态 —— 记忆只有个人的和
  团队的两种，全员没有共享记忆，规矩在 `<userRoot>/rules.md`。
- 切换只换内容、**不改变宽度**：换 tab 时内容原地淡入一次（240ms，`detail-in`），
  换人（`Solo ▾`）时这一栏淡入一次（160ms），整块右栏不重放滑入。
- 三个 tab 是同一根横条上的三段文字，选中态是 `--ink` + 底部 2px `--accent`，不是胶囊。
  tab 条和上面的身份卡之间留 14px，贴着卡片会读成卡片的一部分。
- 详情里点成员 → 技能 / 记忆跟着切到那个人，并自动跳到详情（栏顶出现「‹ 返回」）。
- **开关只有顶栏那颗「详情」**：栏里不再留收起键（那颗 × 和开关是同一件事，挨着内容反而挡路）。
  没有可返回的层级时，栏顶那条 56 的抬头整条不画 —— 空着一条横线像漏了东西。
  手机上是整屏浮层，出不去，所以只在窄屏留着那个 ×。
- **手机（≤640px）**：右栏是整屏浮层，三个 tab 变成顶部的分段控件。
- 打开右栏不改变当前消息的已读状态，也不暂停 SSE。

### 1.3 侧栏：仍然一列平铺、两行

v3 的结论不变（我的原话：不要分组，直接平铺）。v4 只改一件事：**状态改成真的。**

- 行高 60（`min-height`），头像 36（`--av-md`，圆角方图不是正圆），左右内边距 10。48/28 那一档两行字挤在一起，
  头像也认不出是谁；侧栏加宽到 288 就是为了装下这一档。
- 第一行：名字 15/600（团队频道后面跟一个 11px 的「团队」小标）+ **身份** 12px（私聊行，
  `people[].title`）+ **行尾**相对时间 12px `--mono`。身份**吃满名字和时间之间剩下的宽度**
  （早先卡死 5.5em，「小恐龙团队 · 前端工程师」只剩「小恐龙团…」，等于白占这一行）；
  挤不开时身份先省略，名字不参与压缩（最多占行宽 55%）。
- 第二行：最后一句，14/20 `--ink-3`，单行省略。两行之间隔 2px。时间不再挤在第二行里和预览抢宽度。
- **状态不写字，画在头像上**：在想 / 在做时头像外面一圈 `--live` 的光（呼吸 1.6–1.8s），
  待命与睡了是干净的。原来那格文字（`待命` / `在做`）已经让给身份 —— 状态是暂时的，
  身份是这条行真正的信息；一列里每行都写「待命」等于什么都没说。
- 状态来源从「最后一条消息猜」换成 `/api/org` 的 `people[].activity`（🆕）。
  取不到就当待命（不亮圈）——**不要用时间猜**，猜错比不显示更糟。
- **未读分两种底，不靠徽标认**：有人在 @ 我（`mentions > 0`）= 红底（`--danger` 9%），
  只是有新消息 = 浅灰底（`--hover`），当前打开的那一行两种底都不上。徽标也分两种
  （`data-kind="mention"` / `"unread"`）。点开频道 → 已读上报 → 列表重拉，底和徽标当场清掉；
  不清的话要等下一次组织推送，实测就是「点开频道，红点还在」。
- **第一格永远是助理**（身份目录在应用根 `assistant/` 下的那个人，ADR-058）。每个成员都由装配（`ensureOwnerDm`，开机补建 + 招人即建）带一个和我的
  私聊，所以这一格通常直接是真实会话；私聊还没建出来的那一瞬，这一格是**入口**：
  第二行写他的身份而不是消息预览（没有历史，不能编一句「还没有消息」），
  点下去 `POST /api/people/:slug/dm` 把频道建出来。
- **品牌行右端有一个「＋」**：点开拉群浮层（§1.5）。它长出来的是一格会话，不是一项
  「管理」，所以不在列表脚下、和团队 / 插件 / 设置不混在一起。
- **没有「工作区 / N 人 · N 个会话」那行标题。** 侧栏第一行就是会话列表：
  人数和会话数看列表本身就有，多一行只占高度。
- **「团队管理」「插件」「偏好设置」不在这栏里**：它们是应用级的「管理」，
  和最左那列（§1.1）的聊天 / 后台任务住在同一个竖条上 —— 那三格挤在会话列表脚下时，
  既像会话又不像，读起来最费劲。列表脚下只剩一个 `sidebar.footer` 插槽（插件的地盘，
  空时不占一行）。

### 1.4 主列的三段

1. **标题行 52px**：名字 15/500 + 副标题 12px `--ink-3`（私聊写**他的职务**，从名册取；群聊写人数。**不写团队 slug** —— `xiaokonglong` 是目录名，标题已经写着团队名）+ 右侧两个动作
   （找你、详情）。团队、插件与设置住在最左那列（§1.1）。标题行不画大标题，理由同 v3：
   会把眼睛从消息上拽走。返回键只在手机上出现（≤640px 一次只显示一格），桌面上点它是空操作。
2. **消息流**：`overflow-anchor: none`，自己管滚动（见 §7.4）。
3. **输入区**：输入卡（§7）。输入卡上方没有活动条（§4）。

### 1.5 页面：设置、通讯录、插件（拉群仍是浮层）

> v6 起**「通讯录」整屏已删**（ADR-083）：团队与成员就是侧栏里的行 + 右栏的团队资料。
> 下面讲通讯录的那一段是 v5 的决策记录，留着说明当时的取舍；实现与验收以 §13 为准。

这三样是**应用的第二屏**，和手机上的任务屏同一个骨架（`.page`）：**左栏 288 + 右栏正文**。
桌面上「后台任务」不走这套骨架 —— 它是右栏的一态（§2.3），不进整屏。
左栏是「这一屏有哪些东西」（人 / 插件 / 分区），右栏是选中那一个的详情；两栏各自滚，
抬头都是 56 高。**左栏标题就是聊天那行「聊天」**：品牌字 18/600、字距 0.04em，
靠上排、和导航第一格的上沿齐平（不居中 —— 居中会在屏幕顶上留一条空）；
右栏抬头仍是 15/600，它是正文的标题，不是一列清单的名字。这几屏（聊天 / 通讯录 /
插件 / 设置，以及手机上的后台任务）的头因此落在同一条线上。288 就是聊天列表的宽度（`--sidebar` 的桌面值）—— 同一个人、同一个名字，
在聊天和通讯录里落在同一条竖线上。它们**不盖在聊天上**，也没有只为关闭存在的 × ——
离开靠 Esc，或者点最左那列的第一格「聊天」。
只有**拉群**和**装完插件后的重启询问**还是浮层（`.team`）：那是一次性的动作，不是「去哪儿」。
**同一时刻只画一屏**：`App.tsx` 里 `view` 只算一次，`data-view` 和按屏画的那几行都读它；
`store` 里打开任何一屏也让其它屏让路。两屏同时开着会叠在一起互相压住（实测踩过）。

**为什么改**（原来是横跨整屏的一页：抬头拉满、内容挤在左边 760 里，右边一片空）：
一屏只有一件事却没有「选中」这层结构，读起来像没画完；而且抬头拉满一千多像素，
和下面这列字根本不在一根轴上。收成两栏之后，抬头、清单、正文共用两条竖线，
管理员再多的插件也不至于长成一堵墙。

**为什么改**（原来是三个浮层）：① 遮罩底下压着聊天，「点一下外面」和「点里面某个东西」
只差 24px，误关是常态；② 浮层里不能有第二个浮层，设置里的插件分区想再开东西就没地方放；
③ 浮层是临时的，页面是可停留的 —— 通讯录、插件清单这类东西值得停在上面看，
刷新、切回来都还在（`data-view` 记在外壳上）。代价是它们从「随手开」变成「离开聊天」，
所以只有管理类的三样搬过去，「找你」「拉群」这些动作仍留在浮层里。

> **v6 落地（2026-11-06，ADR-084 / ADR-087）**：设置不再两栏 —— 一列卡片（`.set-scroll`），
> 一行 = 27 的图标格（`--raised` 底、圆角 7，线稿 16）+ 标题 14.5/20 + 说明 11.5/16 +
> 右端控件，行间细线从图标右边（52px）起；「更新」一张卡里是**更新代理**（只给桌面版
> 下载安装包用）。资料页的 `.prof-row` 用同一套行形状。下面几段的两栏描述是 v5 的历史。

- **设置是两栏**：左边一列分区（`.page-side`，288 宽，图标 17 + 字 13.5/20，
  每行 36 高、圆角 8，选中用 `--active`），右栏抬头是分区名（15/600）、正文限宽 720。
  分区图标取插槽格子的 `icon`，没给也留出那一格 —— 几行字得对在同一条竖线上。
  **为什么改**：原来是一列往下滚的长页，插件一组册就变成「外观 + 模型 + 以后每装一个插件一截」，
  分区越多越长、越找不着；两栏之后「加一格分区」不再挤占别人的位置。
  窄屏（≤640）两栏折成上下：分区在上（最多 42vh，多了自己滚），正文在下。
- **设置·行**：一行一个设置，左边标题 14/500 + 说明 12.5 `--ink-3`，右边控件靠右
  （`.settings-row*`，宿主提供，插件照样用）。行与行之间一条 0.5px 线，第一行上方也有一条。
- **设置·外观**：三张主题卡（跟随系统 / 浅色 / 深色），104 高、图标在上、字在下，
  选中用 `ink` 7% 的填充 + 加深的边线，不画对勾。三张卡**等高** ——
  只有一张带副标题会让整排一边高一边矮，所以副标题要么都有、要么都没有
  （一句话说明在卡上面那行说明里）。
- **设置·数据**：最底一格，只有一行「重置所有数据」。按钮是红字的危险操作；点开先起一个
  确认浮层（`.team` 同款，和拉群一个模子），写清**删什么**（成员 / 团队 / 频道 / 聊天记录 /
  记忆 / 技能 / 附件 / 日志 / 模型配置），确认后才请求 `POST /api/reset`。清掉模型配置是有意的
  （ADR-089）：重开后模型清单是空的，界面进引导页（§13.9）。
  成功后就地写「已重置，正在重新启动…」—— 桌面壳会重开整个应用，不需要第二个按钮。
- **通讯录**：一行一个人，两行字（名字 13/500 + 身份 12 `--ink-3`），右端是状态
  （在想 / 在做 用 `--live`，其余 `--ink-3`）。**整行可点**：点开和这个人的私聊，这一屏同时退回聊天。
  清单就是左栏那 288（和聊天列表同宽），**右栏空着** —— 通讯录里没有「某个人的详情」
  可看（职务、状态已经在行里了），点一行就是去私聊；摆一块只有名字的假详情板是骗人。
  人数只在标题上写一次，底部不再重复一行「共 N 人」。
  手机上一屏只留这一列（`.page-single`，右栏直接不画）。
- **拉群**：群名一行（`maxLength` 40）+ 成员名单（复用 `.crew` 行，右侧一个 18px 圆勾，
  选中时 `--accent-wash` 底；名单超过 300px 自己滚，建群按钮始终露在外面）。
  我自己一定在群里，所以至少要选一个人；没选够时按钮 `disabled`（40% 透明），不弹错误。
  建完直接进那个群，浮层不留在原地「显示结果」。失败（重名 / 人不存在）把后端那句
  中文摆在按钮上方。
- 三个浮层都从中间淡入、上浮 6px 并缩到 0.985（`sheet-in` 200ms）+ 背景 `veil-in` 160ms；
  `prefers-reduced-motion` 下不动。`Esc` 关最上面那一层（§7.2）。
- **点遮罩空白处就关**：× 在头的右端，不是紧跟标题。

## 2. 聊天流：一行是什么

### 2.1 行的种类（定死）

| 行 | 什么时候 | 默认高度 |
|---|---|---|
| `say` | 人说的话（`kind: "chat"`） | 一行头 + 正文 |
| `live` | **正在跑的一轮**（派生，不落库）：某个人在这个频道里被叫醒、还没回话 | 一行 |
| `note` | 系统留痕（**只画后台命令那条**，`noteOf: "run"`；其余不画，ADR-047） | 24px |
| `divider` | 时间分隔 | 32px |
| `pending` | 🆕 排队中的我的消息（P2，暂不画） | — |

**聊天流里只有聊天消息。** 以前私聊会画 `work` 行（一轮的步数与摘要），群聊什么都不画；
这两半都不对——对话被过程打断，而「他此刻在做什么」在哪都看不见。现在过程只有两个出口：
**跑的时候一条 `live` 占位**，**跑完进这个人的后台任务**（§2.3，ADR-046）。
`work` 行与 `buildWorkRows` 已删除。

### 2.2 `say` 行：**两边都是气泡**

v4 把「平铺 / 气泡」的选择收掉了：**所有人都是气泡**。理由：这是多 agent 的群聊，
一条消息属于谁必须一眼看出；平铺模式下连续发言会糊成一整段，谁是第三条的主人要数头像。

```
   24px  Solo  助理  20:08
         ┌──────────────────────────────────┐
         │ Solo 项目已立并开工…             │
         └──────────────────────────────────┘

                        我  20:12  24px
         ┌──────────────────────┐
         │ 先把失败的那条修掉。 │
         └──────────────────────┘
```

- **别人**：底色 `--bubble`（浅色 = `--raised` 那档灰；深色 = `#121212`，只比纸亮一丝，靠圆角和留白分开，不是一块浮起来的亮砖），正文 `--ink`；**我**：底色 `--bubble-own`（浅色 = `--accent-wash` 的淡蓝，深色 = `#1b1b1b` —— 设计稿里两条气泡都不带颜色，只差一档亮度），整行靠右。
- 两边同一套几何：圆角 **16，只有背对头像的那一角收成 8**（气泡的「嘴」；我那条左右镜像，
  嘴在左上）、padding `12 / 16`、`width: fit-content`、`max-width: 68ch`、
  `overflow-wrap: anywhere`。**不是整宽色带** —— 短句就是一小块，长段落最多 68ch。
- 名字行在气泡**外面、上面**，气泡里只放正文：名字 13/500 · 角色 11 · 时间 10 mono。
  我自己那条只留 `我 + 时间`，靠右。
- 头像 40px，在气泡那一侧的外面。同一个人连续发言（2 分钟内）：只有第一条画头像和名字，
  `需要你` 那条例外 —— 标签挂在名字行里，名字行得留着；
  后续气泡缩进对齐，并把嘴那一侧的角收成 4px：

  ```css
  .row-say[data-grouped="true"] .row-body > .md { border-start-start-radius: 8px; }
  .row-say[data-owner="true"][data-cont="true"] .row-body > .md {
  	border-start-start-radius: 4px;
  	border-end-start-radius: 4px;
  }
  ```

- **气泡里不放时间**（时间在名字行），只有连续发言的第一条显示。
- `需要你` 仍是名字行里一条 1px 竖线 + 12px 文字，**不画在气泡上**（药丸会被读成按钮）。
- 名字行末尾**不挂任何步数**：消息与过程之间没有连线，过程只在他的任务面板里（§2.7，ADR-046）。
- 正文里的 `@某人` 高亮（`.md-at`：14% accent 底 + accent 字）。判据只认**行首或空白之后**的
  `@`，所以邮箱不点亮；行内代码里的 `@` 也不点亮。派活的消息常常一句@好几个人，
  不点亮就要逐字找。
- 附件消息：图片放进气泡，图片自身圆角 12；纯附件消息不排占位正文。
- **点头像 = 看这个人**：跳到他的资料屏（我没有档案页，我自己的头像不响应）。
- **点一条消息 = 动作层**（稿子 19）：底下压一层，原文先复述两行，下面三件事 ——
  复制文字 / 引用回复 / 看看是谁 · 名字（我的消息没有第三项）；「取消」单独一颗。
  链接、代码块、按钮和正在选字时不弹（各有各的用处）。
- 深色下 `--bubble` 与 `--field` 同值（`18 18 18`），别人的气泡和输入卡同色 —— 这是刻意的：
  两档灰已经不够分第三层，再加一档就成了「三块玻璃」。

### 2.3 过程：`live` 行与后台任务

过程有**两个**出口（ADR-046 / ADR-062）：**跑的时候一条占位**；**全部**进这个人的任务面板。
聊天流里**不画过程块** —— 那一块和面板是同一份事实，画两遍只会挡消息（ADR-054 已被
ADR-062 取代）。步骤树只在后台任务面板里画。

#### `live` 行 —— 正在跑的那一句

一个人在这个频道里被叫醒、还没回话，聊天流里就有一条他的占位，位置就是回复将来会落的
地方（触发消息之后）。

```
(40) Solo  助理                       ● 在想…
     ┌────────────────────────────────────────┐
     │ 运行 npm test · 第 3/6 步      1m 12s  │
     └────────────────────────────────────────┘
```

- **它不是消息。** 不落库、不进 `messages`、刷新之后不会出现；由这一轮的 `trace` 帧现算
  （`status === "running"`）。跑完就消失，真实回复由 `create` 落进来。
- **只报「做到哪一步」**：最新一步的标题、`N 步`、从触发消息算起的耗时。还没有任何
  步骤时写「在想…」。**绝不编造他打算说什么** —— C-007 没有 token 流。
- 头像 40px、落在消息列的头像格里，跑的时候是 `working` 态；名字 13/500，步数与耗时
  `--mono` 11px `--ink-3`。
- 一行，不折叠、不可展开。点它 → 打开这个人的任务面板。
- 在跑一条命令时，标题后面跟命令本身（`--mono` 11px、`34ch` 截断）—— 只写「运行命令」
  等于没说。
- 收掉的判据：`replySeq` 出现。`trace` 的结算帧比 `create` 慢半拍时，纯函数按「同一个人
  已经在这条触发消息之后说过话」提前收 —— 同一件事不能同时画两条。
- 一个人在这个频道里被叫醒两次 → 两条占位，按 `startedAt` 排。
- **历史不补占位**：刷新之后这一行就没了，那一轮在面板里。

#### 后台任务（`tasks`）：桌面上是右栏的一态，手机上是第二屏

过程唯一的家。它**不再是从右侧盖在聊天上的抽屉**：一轮的过程要摊开写，380px 装不下。

> **v6 落地（2026-11-06，ADR-084）**：以稿子 07 为准 —— 资料 / 后台任务都是一次整屏
> （`.detail`），不再是「桌面右栏 372 + 手机整屏」两套。一列：上面是谁，下面按天分组；
> 一行 = 一轮（频道 · 时刻 · 正在跑 / 耗时、两行正文、右折角；**左圆点已去掉**，省一列），
> 点开就在那一行下面接着走（整行 `rgb(255 255 255 / .025)` 的淡底 + 一条 0.5px 线），
> 引文在左缘 2px 竖线里，步骤 22px 一行（7px 圆点、13/22 **单行省略**的标题、`--mono` 9.5
> 的时刻与 10 的耗时），最后一行写这一轮怎么收的（「● 已交付 · 11:14」/「● 没答上来」/
> 「● 被新消息合并」），命令块是 `--raised` 底 + 1px `--rule` 描边。跑着的那行右端是步数
> （「12 步」），跑完才换成耗时；`aborted` 的标签是「被新消息合并」，不是「没回话」。
> 下面几段里的「右栏 / 两栏 / tab」是 v5 的历史取舍，讲得通的部分（数据来源、0 步不占一行、
> 轮询）仍然成立。

- **桌面（>1100px）：右栏整块换成它。** 点最左那格「后台任务」（或点聊天流里的 `live` 行），

- **左栏是「一个人跑过的轮次」**，不是「所有人的任务」。人像条（成员，我不算）在上面：
  正在跑的排前面，其余按最近一轮倒序、一轮都没跑过的垫底。默认选「这个频道里正在跑的
  那个人」→ 私聊对象 → 最近跑过的那个。换人就是换这一整个列表。
- **一行 = 一轮 = 一次唤醒。** 第一行「频道名 · `startedAt` · 耗时」，第二行是触发消息的
  正文（两行截断，完整原文去频道里看）。分「正在跑 / 已完成 / 失败 / 被新消息合并」四组，
  组头是 `--mono` 10px 的小字 + 条数，**点一下就收起来**（`aria-expanded`，chevron 转 90°；
  默认全展开 —— 第一眼要看的是「都跑过什么」，收起是十三轮摊不开时的退路）。选中的那行是 `--active` 底。**没有卡片、没有色点**：
  状态写在右边那栏的抬头里，列表只负责「是哪一轮」。
- **右栏 = 这一轮。** 抬头一行：头像 26、名字、职务、一条竖线、频道名，右端 `N 步` /
  状态 / 耗时。下面是「触发的那句话」（左缘 2px 竖线，像引用）和「这一轮做了什么」。
- **步骤是时间轴**：62px 的时刻列（`--mono` 10px、右对齐）、一根 1px `--rule` 竖线、
  内容列。内容列一行是「类型 + 标题（`--mono` 11.5、单行截断）+ 耗时」。
- 只有**有机器产物**的步骤能点开（`run` / `file-*` / `think`）：点开在下面给一块
  `--raised` 的等宽块 —— `$ 命令`、输出（≤ 320px 滚动）、`退出码 N · 耗时`。没产物的行
  按钮是 disabled，不弹「没有过程」。**同时只展开一个步骤**。
- 列表在选中的人还在跑时每 2 秒重拉一次；不在跑就不拉（ADR-017）。轮询拿回的是折叠帧
  （不带步骤）：**已经有步骤的那一轮不能被它冲回「还没读」**，`upsertRun` 在新帧没有
  `steps` 时留着旧的那份。步骤没到就什么都不画 —— 写一行加载字只会闪一下。
- **0 步的一轮不占一行**：只说了句话、没动过手（包括没回话的），那是聊天不是任务；还在跑的先留着，步数随后才到。
- Esc 回聊天；手机上这一屏是一条（列表在上、详情在下），列表头上有一个返回键。
  桌面上 Esc 与栏顶的收起键都回到「资料」，不是退出到聊天 —— 聊天本来就没走。

**步骤树**（只在后台任务那一栏用 —— 聊天流里的过程行已经删了，ADR-062）：

- **说话不进步骤树。** 一轮里说出口的话是那条频道消息；画成步骤会在原文上再抄一遍。
  步骤只有「做」：思考、跑命令、读写文件、翻记录、记记忆、招人、其他工具。
- **0 步的那一轮不给箭头**：想完直接说话、没动手，没有过程可展开。
  有步数但取不到步骤（比面板窗口更早）时才写那一句「这一轮没有留下过程」。
- 步骤行高 28px，左缘缩进 20px（`▸` 的走廊），竖线 1px `--rule` 贯穿，最后一格收口。
- 图标只有三种：思考（一个点）、终端（`>_`）、文件（页角折起）。15px `--ink-2` 描边，
  **没有彩色图标底**；未知工具画一个方框问号。
- 步骤标题 13/22 `--ink-2`，**单行省略**（全文点开这一步看）；耗时 / 退出码 / 增删行数用 `--mono` 11px `--ink-3`。

- chevron 14px（SVG，`--ink-2`，笔画 2.2），收起朝右、展开转 90° 朝下（160ms，
  `prefers-reduced-motion` 时不做过渡）。
- **展开/折叠的记忆**：`localStorage["solo.trace.open"]`，键 `<channelId>:<seq>:<slug>`；
  只记「用户手动改过」的，没改过的走默认（在跑的默认展开，历史的默认收起）。


### 2.4 四种步骤的详情

**命令（`run`）**

```
$ npm test
  ✓ 3.2s · 退出码 0 · 412 行输出
  ┌──────────────────────────────────────────────┐
  │ ✓ test/core/channel/post.test.ts (12)        │
  │ ✓ test/core/agent/roster.test.ts (8)         │
  │ …                                            │
  └──────────────────────────────────────────────┘
```

- 命令本身 12/18 `--mono`，前面一个 `$`（`--ink-3`）。
- 输出区：`--raised` 底、圆角 8、内边距 10/12、`max-height: 320px`、可滚、
  12/18 `--mono`、`white-space: pre`、**`textContent` 灌入，不过 Markdown**。
- **ANSI 转义先剥掉**（后端做，前端再做一次兜底）：控制字符会让整块变成乱码。
- 截断：单步输出上限 8 KB，尾部写 `… 共 N 行，已截断`。
- 退出码非 0：输出区顶部一行 12px `--danger` 的 `退出码 1`；**不把整块染红**。

**文件读（`file` read）**：一行 `读了 <path>`，展开显示文件头 40 行 + `… 共 N 行`。

**文件写（`file` write）**：折叠行右端 `+12`（写入行数）；展开显示路径与行数。

- **没有 diff，也不画 `−N`。** 会话条目里只有写入的内容，没有写入前的旧文件；
  自己拼一个「删了几行」就是编数据（§8.2 ①）。
- 因此 `--add` / `--del` 两档色没有消费者，**不定义** —— 少一个没人用的 token，
  就少一个下一个人以为「这里有 diff」的错觉。

**思考（`thinking`）**：折叠成 `思考 12s`；展开是正文，13/22 `--ink-2`、`pre-wrap`、
不过 Markdown（模型可能在思考里写 `**`，渲染出来反而像在强调）。
被安全过滤的思考只有 `思考（已隐藏）`，不可展开。
**连续的 thinking 合并成一条**，时长累加 —— 一条一轮里可能出现十几次，逐条画就是噪音。

**说话（`say` 工具）**：`在 #demo 说了一句`，点击滚到那条消息并高亮 1.2s。
被 `[PASS]` 吃掉的轮次不画步骤。

### 2.5 `note` 与 `divider`

不变（v3 §5.3 / §5.5）：`note` 12px `--ink-3` + 左侧 1px 竖线；时间分隔 12px 居中、
`--ink-3`、上下 26 / 18（它是路标不是消息，要比正文安静），同一天间隔 > 30 分钟才插。

**但系统留痕不进聊天流了（ADR-047）**：报到、没答上来、看门狗都是灰字，
一屏对话里插五六条，读起来像日志。它们仍在库里、`chats` 读得到，只是这一屏不画；
`note` 行只剩下面那种后台命令留痕。

**后台命令的留痕（`noteOf: "run"`）收成一行**：只露首行 `后台命令跑完了。` + 时间，
点开是等宽字体的全文（最多 320px 高，超出滚动）。它天生是一坨终端输出、是写给起跑
那个人的，平铺进对话就是二十行日志 —— 我扫一眼会以为频道坏了。

### 2.6 一轮的边界怎么画

- **一轮 = 一次唤醒。** 他在团队频道干活时我私聊插一句，是**新一轮**（`WakeRecord.reply`
  换了）；任务面板里另起一块，块头的触发消息就是那句插话。
- 一轮里他跨频道说了话（结论回 `task` 频道），那是那条频道里的消息，**不在当前频道插入
  一条假消息**，也不进步骤树。
- 面板里两块之间 12px；同一轮在聊天流里的 `live` 行最多一条。

### 2.7 空频道

空频道**还没开始**，不是出错 —— 所以不贴左上角（那读起来像加载失败），整块居中偏上，
下面大半屏留给输入卡。内容装在**一张小卡**里（宽 320、`--field` 底、0.5px `--line`、
20 圆角、内边距 `28 / 24 / 24`）—— 一行字漂在整片空地里，读起来像没加载出来。
三样东西，从上到下：

| 元素 | 内容 | 数据来源 |
|---|---|---|
| 头像 | 频道里非我的人，64px，圆角 30%（和别处同一档，不是正圆，也不加外圈）；一个人是单头像，几个人是叠起来的群体头像 | `detail.members`（`GET /api/channels/:id`） |
| 标题 15/500 | 私聊 `还没和 X 说过话`；群聊 `这个频道还没有消息` | 同上，`channel.kind` |
| 说明 13 `--ink-3` | 私聊 `直接说你想做什么，他会回你。`；群聊 `说点什么，或者 @ 一个人开始。` | 静态文案 |
| `@名字` 胶囊（只群聊） | 最多 4 个，点一下把 `@名字 ` 写进输入框，**不直接发** | `detail.members` |

**没有「从谁开始」这种问句**：问句把决定推回给我，而这里要回答的正是「我该说什么」。
说明行直接给动作。私聊不画胶囊 —— 私聊里没有第二个人可选。

### 2.8 插件插槽（`sidebar.footer` / `rightPanel.tab`）与插件开关

最左那列那一格「插件」（`#plugins-btn`）打开插件页（`PluginsPage.tsx`，应用的第二屏，
不是浮层也不是插槽）。它读 `GET /api/plugins`
（`name` / `slug` / `description` / `enabled` / `error` / `brings`）：

- **左栏是清单，右栏是选中那个的详情**。左栏一行一个名字（34 高、圆角 8，选中用
  `--active`），行尾一颗 6px 的点：开着是 `--live`，关着是凹下去的 `--ink-3`。
  名字和目录名不一样时，右栏抬头用等宽小字带上目录名 —— 两个同名插件必须分得开。
- **右栏**：抬头是名字 + 「删除」+ 开关；正文是说明、**它带来了什么**
  （`brings` → 「工具 clock、一段提示词」）和目录（`plugins/<slug>/`，等宽）。
  删除是**同一个按钮点两次**（第一次变红的「确认删除」，4 秒不动自己收回）—— 不用 `window.confirm`，
  桌面壳里那个对话框会被吞掉，点了像没反应（实测踩过）。
- `brings` 缺失而插件是开着的、也没有 `error`，写「还没装上 · 看一眼日志里的 [plugin]」——
  正常开关 / 装 / 卸之后它当场就有（重装是同步做完才返回的）。
- **装插件是标题右边那颗「+」**（`plugin-add`）：和聊天标题旁的拉群同款、同位置 ——
  装一个插件就是给这一列加一格。那颗「+」里套着隐藏的 `<input type="file" webkitdirectory>`，
  点它唤起系统文件夹选择器；选中后清单顶上出现一条「已选「名字」（N 个文件）」+「安装」，
  两段式确认，避免误点就把文件夹写进工作区。（以前它在左栏脚下，一条按钮贴在最底，
  离「插件」这个标题八百像素远，像另一件事。）
  前端把每个文件读成 base64、把 `webkitRelativePath` 的第一段当 slug，发 `POST /api/plugins`。
- 装 / 卸 / 开关的后端部分**当场生效**（CORE §13 / ADR-026）；但带 `client.js` 的插件
  装完后，前端入口要等页面启动时才 `import` —— 所以会起一个 `.team` 同款的确认浮层：
  「「X」已经装好了」，说明工具和提示词已生效、界面入口要重启，按钮「稍后 / 立即重启」。
  桌面壳请求 `POST /api/restart`（后端以退出码 75 退出，壳 `app.relaunch()`）；
  网页版没有壳，按钮变成「刷新页面」，`location.reload()` 重新走 `bootPlugins`。
  后端插件装完不弹：它已经能用了，没必要打断正在跑的轮次。

- 插件拿到 `ui = { h, React, api, store, useStore, register }`：`store` 是界面状态的快照 +

  插件组件靠它跟着界面变（订阅读到的状态一变，格子就重画）。
- 插件自带样式的用 `style:` 一段 CSS，宿主插进 `<head>`；宿主只给插槽容器的外部留白，
  不给插件画任何外框。**横排插槽里的东西自己负责尺寸**，否则会把那一行撑开。
- 插槽由宿主文件声明（`SettingsPage.tsx` / `Sidebar.tsx` / `App.tsx` / `Stream.tsx` / `Composer.tsx` /
  `RightPanel.tsx` / `Overlays.tsx`），**加一个插槽 = 登记 `SlotName` + 在宿主里画一个 `<Slot>`**；
  插件不能自己造插槽。`test/ui/plugin.test.ts` 会查「每个 `SlotName` 都有一处宿主」。

## 6. Token 与字

### 6.1 颜色

v3 的 token 全部保留，**新增四档，只给轨迹用**：

```css
:root {
  /* 轨迹：只有这些，没有第五种状态色 */
  --run-line: rgb(38 49 72 / 0.04);   /* 步骤行 hover */
  --run-rule: rgb(0 0 0 / 0.06);      /* 步骤树竖线 */
}
[data-theme="dark"] {
  --run-line: rgb(255 255 255 / 0.05);
  --run-rule: rgb(255 255 255 / 0.08);
}
```

**规则没变，只多一条：**

1. 颜色只上数据，不上 chrome。
2. 一个强调色（`--accent`）。**填满的按钮另用 `--accent-solid`**：深色下 `--accent` 是链接那种亮蓝，
   白字压上去发虚、像禁用，主按钮因此单开一档（浅色两者同值）。成功/失败不上色：成功一律 `--ink-3`，失败才 `--danger`。
3. 成功一律 `--ink-3`（`✓`），失败才 `--danger`。**不做绿色成功徽章。**
4. 不许渐变、发光、玻璃。阴影仍然只有输入卡和浮层两处。

**品牌标**：一个手写的 S，右下角一颗蓝点（稿子 09）。形状只有一个家：`desktop/icon.svg`；
界面里由 `ui/app/src/lib/brand.ts` 的 `brandMarkSvg` 画同一形状，favicon 是同一形状的
data URI（`ui/app/index.html`）。**只在两处画**：助理的头像（§6.4）与引导页那一格
（§13.9）—— 侧栏头上那行是「聊天」，导航列顶上不放标，再画一遍只会把两列的头断开。
颜色跟主题：浅色白底深墨（外加 1px 的 `--rail-mark-line`，不然白方块和纸粘在一起）、
深色深底米墨，全走 `--rail-mark-*`。
5. 0.5px 是默认线宽；轨迹树的竖线是 1px `--run-rule`（0.5px 的竖线在 2x 屏上会消失）。

### 6.2 字

| 用途 | 字号/行高 | 字重 |
|---|---|---|
| 正文、思考展开 | 14 / 24 | 400 |
| 次级、步骤标题、按钮 | 13 / 20 | 400 / 500 |
| 行名、`run` 折叠行 | 13 / 20 · 14 / 20 | 500 |
| 整屏标题（左栏：聊天 / 通讯录 / 插件 / 设置，手机上的后台任务；品牌字） | 18 / 24 · 字距 0.04em | 600 |
| 频道标题 | 15 / 20 | 500 |
| 命令、输出、数字 | 12 / 18（`--mono`） | 400 |
| meta、时间、耗时、步骤数 | 11 / 14 · 10 / 14（`--mono`） | 400 |

圆角六档不变。轨迹块用 `--r-row`（12）；输出区用 `--r-control`（8）；

间距只有 `4 / 8 / 12 / 16 / 24`。`run` 块与上一条消息 16，块内步骤 0（靠行高），
输出区上 6 下 8。

### 6.4 微动效（正在思考 / 正在跑命令）

**动的是「还在进行」这一个信号，不是装饰。一轮结束，所有循环动画必须停干净。**

| 位置 | 进行中 | 结束 |
|---|---|---|
| 侧栏状态点 | 6px 实心 `--live` + 外圈 3px 12% 呼吸 2s | 点消失，只留 `--ink-3` 文字 |
| 头像 | 整张脸：在想歪头 ±4° 2.2s；在做上下 2px 1.6s（插画是 `<img>`，动的是它自己） | 压扁回弹一次 1.8s |
| `run` 折叠行 | `▸` 换成 3 个 2px 点，透明度 0.25→1 依次错开 0 / 160 / 320ms，周期 1.2s | 换成 `✓`，淡入 120ms |
| 步骤行 · 思考 | 图标是一个呼吸的点；右侧耗时每秒 +1 | 耗时冻结，`▸` 恢复 |
| 步骤行 · 命令 | `>_` 的光标每 1s 闪一次（`steps(2)`）；标题后跟 `…`，每 600ms 在 1/2/3 个之间变 | `✓ 3.2s`，`…` 消失 |
| 命令输出 | 新行从底部追加，不整体重排；只有用户钉底时才自动滚 | 末尾补一行 `退出码 0` |
| 步骤新增 | 120ms 淡入 + `translateY(2px) → 0` | — |

硬规则：

1. **`prefers-reduced-motion: reduce` 时全部 `animation: none`**，只保留文字（耗时、状态）。
2. **不许对 `height` 做 transition**；步骤展开用 FLIP。
3. 计时文本必须 `tabular-nums`，否则每秒跳一下会把整行推来推去。
4. 一轮结束后 **1.2 秒内所有循环动画必须停**：呼吸的点、闪的光标、`…` 全换静态符号。
   留着转的东西会让人以为它还在跑。
5. 不做逐字打字机。C-007 已经证明 token 流不可靠；轨迹按条目更新，输出按行追加。

### 6.5 头像

**一个人一张插画，画在服务端**（`GET /api/avatar/:seed`，`src/app/avatar.ts`）。

- 画风只有一种：DiceBear 的 `micah`。混着用别的画风会像从四个网站抠来的图标。
- **种子是 slug**，不是显示名：改了称呼还是他，脸不跟着变。同一张脸永远同一张。
- 取景只留上半身：原稿是一张半身像，脸在整张图里只占四成；放大到 `scale 170`、
  往下 `translateY 18`，脸才落在圆里。24px 这一档没有这个取景，只剩一团浅色。
- 底色 6 支淡彩（色相各差 60°）按 slug 挑一支，压在三成饱和度上下 —— 和原来那套纸感
  底色一个意思，但因为底是纸、脸是插画，深色主题下要一圈 `--ink` 10% 的描边把它托起来。
- 形状永远是圆（`border-radius: 50%`），尺寸由 `--av-sm / --av-md / --av-lg` 决定：
  列表与消息行 24，轨迹块与消息头像 40，空频道 56，档案页 44，`@` 弹层 20。
- **三态只动整张图**（`.av[data-state]`）：插画是 `<img>`，CSS 够不到里面的眼睛，
  所以没有眨眼，只有整张脸的歪、点头、回弹。
- 浏览器要的是 **2 倍尺寸**（`?size=` 是显示尺寸 × 2）；服务端夹在 16–256，
  一周缓存（不是 `immutable`，画风改了得能过期）。
- **群体头像**（`groupAvatar()`）还是座位表：一个人单张，2 人对角、3 人品字、4 人 2×2，
  后画的座位用 `radial-gradient` 挖洞。小尺寸（24）只排两张 —— 16px 一格的四张脸糊成一片点。
- **助理不画插画**（ADR-083）：他的脸就是程序的标识（那个 S，`lib/brand.ts`
  与 `desktop/icon.svg` 同形），深底浅色，20px 也认得出。判定只认 `assistant` 标记，
  不按名字猜；群头像里他坐的那个座位也画标识。

## 7. 输入区与滚动

### 7.1 输入卡

照 v3 §7，改三处：

- 高度跟着消息列宽走（列宽 + 32）。
- 附件预览缩略图 40×40、圆角 8、右上角 16px 移除按钮。
- **发送后不清空正在排队的提示**（没有排队状态，就不画「排队中」）。
- **`＋` 菜单只能往上长**（`bottom: calc(100% + 8px)`，左缘对齐加号）。输入卡贴着
  屏幕底边，往下开的菜单会整张落到视口外面。
- **三个控件的中线是同一条**：输入行 34（文字 24 + 上下各 5）、发送圆 34、加号 28 的圆
  贴底再抬 3px。卡片上下内边距都是 9，整行落在卡片正中。早先是「文字行 28 + 发送压 3px」，
  看图上加号、文字、发送键各自差两三像素，所以改成同一个 34 的行高。

**有人在等我选时，输入卡换成选项卡。** 判据是纯函数 `pendingChoice()`：最后一条带 `options`
的消息、且它之后我没说过话。卡片从上往下：谁问的（头像 + 名字）→ 问题（可多行）→ 单选项
（`--r-row` 圆角，选中是 `--accent` 细描边 + 7% 填充）→ 「其他…」一行输入 → 底部「跳过 / 提交」。
**选项一行一个、竖着排**（占满卡宽，圆点跟第一行字对齐）—— 选项常是一整句话，横排成几个胶囊
之后读不完，还会把卡撑成好几行；竖排时长短都放得下。
点提交 = 发一条普通消息（正文是选项文字，`replyTo` 指向那条问题），不新增接口。跳过 = 关掉卡片、
什么都不发（输入框回来，想自己打字就打字）。卡片**不进消息流**，它只是输入框的另一种形态。

**菜单一律挂在触发它的按钮上，不用 `position: fixed` 裸摆。** `fixed` 不写
`top`/`left` 时按「静态位置」定位，而菜单在 DOM 里排在页面最后 —— 会掉到视口下方。
所以触发按钮外面套一层 `.menu-anchor`（`position: relative`），菜单用
`position: absolute` 贴着它长：`＋` 菜单往上、顶栏「N 件找你」往下，都是这一条规则。

### 7.3 滚动

- 钉底规则：用户距离底部 < 80px 时，新内容到达自动滚到底；否则不滚，浮一个
  `3 条新消息 ↓` 的胶囊（点击滚到底并清除）。
- **轨迹展开时钉底不算「内容变高」**：展开一个块不触发自动滚底，只在块顶部已经
  在视口外时，用 WAAPI 补 `translateY(-delta)` 140ms，避免内容跳。
- **上翻自动加载更早**：滚到离顶 120px 以内就自己补一页（`hasMore` / `before`），
  没有「加载更早的消息」这个按钮。补的时候滚动区顶上浮一个 14px 的转圈（28px 高的一条），
  补完按锚点行（`data-seq`）补回滚动差值，屏幕上的字不动。短频道一屏没填满时也会接着补。
- 离开底部时右下浮一个「回到最新」胶囊（`position: absolute` 在滚动容器**外面** ——
  放进滚动区就算进 `scrollHeight`，永远差它那几十像素），点了平滑滚到底。

  `@` 提不到任何人，多出来的只是一段字。
- **位置**：贴着光标上方 6px，左缘对齐 `@` 字符；上方空间不足时翻到下方。
  它是浮层（portal + `position: fixed`），不参与输入卡布局。
- **尺寸**：宽 280、最多 6 行（超出滚动）、圆角 12、1px `--line`、
  阴影 `0 8px 24px rgba(0,0,0,.08)`；入场 160ms（opacity + 4px 上浮），退场 120ms。
- **每行 32px**：头像 20 + 名字 13/500 + 身份 11 `--ink-3` + 右侧 `@slug` 10 mono `--ink-3`。
- **键盘**：`↑ ↓` 选、`Enter` / `Tab` 补全、`Esc` 关闭；鼠标悬停也选中。
  选中行只有 `--hover` 底，**不加 accent 边、不加底色块**。
- **补全**写入 `@名字 `（写名字，不写 slug），光标放到空格后。
- **过滤**：`@` 之后继续打的字符按名字 / slug 前缀匹配（`@lin` 命中林越）；
  没有匹配时显示一行 12px `--ink-3` 的 `这个频道里没有叫「xxx」的人`，
  **不自动关闭**，删掉字符能恢复。
- 候选人来自 `GET /api/channels/:id/mentionable`，**只列频道成员**；
  请求失败就关掉弹窗，不阻塞输入。
- **手机**：弹窗贴输入卡上沿，宽 = 屏宽 − 16，行高 44（手指够得着）。

### 8.2 本版新增（已落地；字段以 `docs/WEB-API.md` 为准）

> 全部**只读、从会话派生、不落库**。加接口的同时先改 `docs/WEB-API.md`。

**① 一轮的轨迹**

两条：一个人跑过的轮次（列表，折叠）与某一轮的全文（步骤）。聊天流不再画过程块（ADR-062），
两条都是后台任务的数据源：

```
GET /api/people/:slug/turns?from=<seq>&to=<seq>&limit=<n>
→ { turns: ViewTurn[] }            // 这个人在所有频道里的轮次（任务面板；limit 默认 30、上限 100）

GET /api/channels/:id/turn?seq=<触发这一轮的消息 seq>&slug=<谁>
→ { turn: ViewTurn | null }        // 找不到（那人没被叫醒 / 已过期）就是 null
```

`(seq, slug)` 才唯一确定一轮；人的版本按 `startedAt` 排（跨频道 seq 不可比），
每轮自带 `channelId`。

```ts
type ViewTurn = {
  channelId: string;
  channelTitle?: string;           // 频道显示名（归档 / 删掉之后列表查不到，靠它）
  seq: number;                     // 触发这一轮的消息
  slug: string;
  label: string;
  status: "running" | "done" | "failed" | "aborted";
  startedAt: number;               // = 触发消息的 at
  endedAt?: number;                // = 回复消息的 at；还在跑就没有
  replySeq?: number;               // 他最终说出口的那条
  trigger?: { from: string; text: string };  // 触发这一轮的消息（面板块头；text 截 200 字）
  stepCount: number;               // 折叠行左边的「N 步」
  summary: string;                 // 折叠行右端的确定性摘要（服务端算，不调模型）
  truncated?: true;                // 步骤超过 200 步
  steps?: ViewStep[];              // 只有 /turn 与 SSE trace 带
}

type ViewStep = {
  id: string;                      // 会话条目里的 toolCall id（稳定，前端拿它做 key 与展开状态）
  kind: "think" | "say" | "run" | "file-read" | "file-write"
      | "chats" | "history" | "remember" | "hire" | "tool";
  title: string;                   // 服务端算好的一行人话（见 §2.3 的映射）
  status: "running" | "ok" | "failed";
  ms?: number;                     // 拿不到就不出现
  // 按 kind 出现，互不混用：
  command?: string;                // run
  output?: string;                 // run：≤ 8 KB，已剥 ANSI，尾部带截断说明
  exitCode?: number;               // run
  truncated?: true;                // output 被截断时出现
  path?: string;                   // file-*
  added?: number;                  // file-write：写入行数（**没有 diff**，见 §2.4）
  text?: string;                   // think / say：正文
  tool?: string;                   // 未知工具的原名
}
```

- 一轮的切分：会话条目里 `kind === "core.channel"` 且 `data.channelId/seq` 对上的那条，
  到**下一条** `core.channel` 条目之间。
- **没有 diff / removed。** 会话条目里只有写入的内容，没有写入前的旧文件 —— 画一个
  自己拼出来的「−N 行」就是编数据。所以文件写只显示 `+N`（新增行数），不给 diff。

**② 轨迹推送（实时）**

在 `GET /api/channels/:id/stream` 上加一个事件，**不新开连接**：

| 事件 | data | 何时 |
|---|---|---|
| `trace` | `ViewTurn`（正在跑的那一轮的瘦身快照，一个事件一轮） | 步骤变了才推（服务端按指纹去重，沿用 120ms 提交去抖）；结算时补最后一帧。**有人在跑时服务端每秒补推一次**：状态写在会话的 live 文档里，模型思考那几十秒不落盘，只靠提交总线会让进度行停在「正在执行」、头像不亮圈 |

- 前端按 `(seq, slug)` upsert；只订阅当前频道。私聊频道推的是**这个人的跨频道轮次**
  （服务端用 `personOfChannel()` 认出来），前端按 `(channelId, seq, slug)` upsert 进按人的 `runs` 表
（群聊也走同一张表：`live` 行与任务面板都读它）。
- 一轮跑完推 `status: "done"` 之后**不再推**，界面自己收尾。
- 只推 `steps` 的**截断版**（每步输出 ≤ 2 KB），完整内容点开时再拉 ①。理由：SSE 不该
  搬 8 KB 的终端输出。

**③ 忙闲**

`GET /api/org` 的 `people[]` 加一个字段（不加路由）：

```ts
activity?: {
  state: "thinking" | "working";   // 只报这两种；没有这个键 = 待命
  since: number;                   // 毫秒
  channelId?: string;              // 他这一轮在哪个频道
}
```

- 由会话的 live task 派生（`harness.ownedTasks()`），结算即消失。
- `/api/stream/org` 每帧带完整快照，所以忙闲**免费**跟着现有推送走。

**④ 刻意不做（别再加回来）**

- **不做 `/api/tasks`、不建任务表。** 「后台任务」是**派生的视图**（ADR-046）：一轮就是
  一次唤醒，步骤就是会话条目，面板只是按人重新排一次；没有任务对象、没有状态机、没有落库。
- **不做「正在输入」的逐字草稿**：C-007 已经删过一次，理由是 token 流不可用。`live` 行报的是
  「做到哪一步」，不是「将要说什么」；轨迹按条目推，不按字推。
- **不做 token / 成本**：核心没有这两个对象（CORE §11）。

## 9. 技术栈与工程结构

### 9.1 技术栈（照 DSH，不换）

| 层 | 选择 | 理由 |
|---|---|---|
| 构建 | **Vite 6**（现有 6.x） | DSH `apps/web` 用 `vite ^6.4.3`；同一套，改造成本为 0 |
| 框架 | **React 18 + TS**（现有） | DSH 用 `react ^18.2.0` + `@vitejs/plugin-react`。不引框架、不引组件库 |
| 样式 | **手写 CSS + CSS 变量**（现有） | DSH 用「一个 theme 包 + 每个组件一个 `*.module.css`」。我们只抄 theme 那一半：六档字号、三档灰靠全局变量约束，组件样式按区域进 `styles/*.css`，不引 CSS Modules（组件少，加一层文件跳转不值） |
| 状态 | 现有 `store` + `useSyncExternalStore` | 全部状态就一个对象，不需要状态库 |
| 桌面端 | **已落地**（ADR-028 / ADR-069）：Electron 主进程把内核当子进程拉起，窗口加载它发的同一个 origin（`?shell=desktop&platform=…`） | DSH 也是 Electron 壳加载本地服务；界面零重写，端口由壳分配（7788 被占就换临时端口）。macOS 用系统标题栏，红绿灯与标题单独占顶上一条（ADR-088）；Windows 用 `hidden` + 40px `titleBarOverlay` 藏掉系统标题栏，界面自己画标题带和菜单（`ui/app/src/titlebar/`）。Windows 那套留白与拖拽规则按 `data-os` 分开，浏览器里一像素不变 |

**抄了 DSH 的什么**：Vite + React 18 的构建组合；「消息流里的工具调用是一等公民」这一行模型
（DSH 的 `DiffBlock` / `CommandText` / `CodeCard` / `AnimatedRows` 与本文档的
`FileDiff` / `RunOutput` / `run` 块 / 微动效是同一套词汇）；桌面端做成壳、不重写界面。

**插件层只抄了壳**（ADR-018 / ADR-019）：插槽（`sidebar.footer` / `rightPanel.tab`）与
「插件是文件夹 + 一个 `apply`」这一层借了 DSH 的 client module 形状，但**不搬 Cordis 微内核**
（服务定位器、五种事件派发、boot 图、lazy-CJS）—— 插件只能拿到 `h` / `React` / 接口客户端 /
`register`，看不到别的插件的模块，跨插件协作只经插槽。VFS 预览仍然没抄。

**套壳没有额外接缝**：窗口加载的就是后端同一个 `http://127.0.0.1:<port>/`，
`localStorage` / `navigator.clipboard` / 外链在 Electron 里行为一致，所以原先设想的
`platform.ts` 网关没有建（ADR-028）。为壳而加的样式只剩一组：
Windows（`…[data-os="win32"]`）在框顶加一条 40px 标题带，菜单、拖拽把手和右边 140px 的
系统按钮让位都在里面。macOS 用系统标题栏，界面不为红绿灯让位（ADR-088）——
原先压在侧栏那一组规则已删。这组只在壳里生效，浏览器里一像素不变。

## 13. v6：一份内容表，两套摆法（手机 / 桌面）

v4 只写了一套宽屏布局，手机是它的窄版（右栏变浮层、导航变底栏）。v6 把这个关系说清楚：
**内容和字的档位只有一份，摆法随设备变。** 改布局之前先读这一节，别再为桌面另起一套小字。

### 13.1 一条规矩：内容表一份，入口随设备变

同一件事在两端必须是**同一张表、同一个顺序、同一组字段**；允许不同的只有：

- **摆法只有一套（2026-11-06 改，ADR-084）**：两端都是「一屏只放一件事、往下钻」——
  首屏是和助理的对话，左上「对话」、右上「设置」两颗门（2026-11-06 调整：对话挪到左上，和别的对话的返回同一处）；别的对话是「返回 + 名字 + 资料」；
  资料 / 后台任务 / 设置各占一次整屏。宽窗口里这一列最宽 **860** 居中，不另起一套三栏。
- **入口只有一个**：资料从对话右上那颗人像进，后台任务是资料表的最后一行；设置从对话
  或列表的标题栏进。没有「另一个地方」能直接到任务。
- **密度**：桌面窗口再宽，消息列也不超过 640（`stream.css` 的 `.flow-inner`）；**一行的字级、卡片的顺序、字段的名字**两端逐项相同。
- **换屏有动画（2026-11-06）**：进哪一屏，那一屏淡入并从下面浮 6px（220ms，`page-in`），
  列表 ↔ 对话、整屏页、资料 / 后台任务都是同一条；收起不画退出动画（退得太慢会挡下一次点击）。
  `prefers-reduced-motion` 时整条跳过。

**不许出现的差异**：一端有的字段另一端没有；一端叫「资料」另一端叫「详情」；一端 15 正文
另一端 13。发现对不上，先改稿子再改代码。

**输入卡两端是同一张**（2026-11-06 改）：一整颗胶囊（圆角 25、高 50、`--card` 底 + 0.5px
描边 + 一层投影），左端一个圆钮（上传 / `＋`），右端一个 34 的圆钮（发送）。桌面**不许**
另起一套更窄的直角卡：它只是宽度跟着消息列（640）走、居中，其余逐项相同。
桌面上「Enter 发送 · Shift+Enter 换行」那行小字删掉 —— 手机上放不下，桌面就不该多一样东西。

**同一个状态只有一个词**：后端 `activity` 只有四档（`idle` / `thinking` / `working` / `asleep`），
界面固定翻成 **待命 / 在想 / 在做 / 睡了**（`Overlays.tsx` 的 `PRESENCE_TEXT`）。不许在
稿子里写「在的」「刚说完话」「正在干活」这类没有字段支撑的说法 —— 「刚说完话」是把时间
再翻译一遍，同一件事会出现两种说法。

### 13.2 右栏这张表（两端同一份）

从栏顶往下，顺序固定：

| 顺序 | 人（助理 / 成员） | 团队频道 |
|---|---|---|
| 1 | 身份：头像、名字、一行副标题 `职务 · 状态`（`ViewActor.title` + `people[].activity` 的四档：待命 / 在想 / 在做 / 睡了；模型在第 3 行单独一行，副标题里不重复） | 身份：群头像（按 `members` 画）、团队名、`团队 · N 人` |
| 2 | 一行统计：今天 N 轮 · 共 Xm · 最近… | 一行统计：记忆 N 条 · 成员 N 人 |
| 3 | 模型 | 成员（四列网格，头像下是名字；我在最后一格、点不动） |
| 4 | 预置词（他本人的 `identity.md`） | 团队介绍（`README.md` 正文） |
| 5 | 记忆 N 条 | 团队记忆 N 条（只读） |
| 6 | 技能 N 个（个人 / 团队 / 全员三层，同名的盖） | 团队技能 N 个 |
| 7 | 工作空间 `workspace/`（点开是文件） | — |
| 8 | 后台任务 N 轮 | — |

**身份块居中，统计在它里面**（稿子 06 / 08）：头像 72、名字 20/600、一行副标题、一行统计，
全部居中；统计不另起一张卡，就和身份同一块。

**顺序为什么是这样**：先「这是谁」（身份 + 统计），再「他手里有什么」（模型 / 成员），
再「他记得什么、会什么」（记忆 / 技能），最后才是「他的桌子和跑过的活」（工作空间 /
后台任务）。团队那列把成员放前面：一个群频道最先要回答的是「这个群里有谁」。

**为什么人比团队多两行**：模型是「这只手」，工作空间是「他的桌子」；团队没有这两样 ——
团队频道里跑活的是人，模型跟着人走。**团队不画「建成时间」**：`README.md` 里没有这个字段，
后端也没有（§8 的规矩）。团队文档写了 `doing`（一句话现状）时，那一行挂在成员前面
（`ViewChannel.doing`，不写就不画）。

> **这一节改掉了 §1.2 的 tab**：v4 的右栏是「详情 / 技能 / 记忆 / 文件」四个 tab，
> v6 把它收成**一张平铺的表**（上面这八行，顺序固定，不用切）。理由：四个 tab 里
> 「详情」装了身份 + 成员，另外三个各装一样，切来切去只为看同一份东西的不同段落；
> 一屏往下滚反而更快，也才谈得上「两端同一张表」。**已落地**（2026-11-06，ADR-083）：
> `RightPanel.tsx` 只剩这张表，`tab` 状态与手机上的分段控件都已删掉。

**统计行不新增接口，现算**：人的「今天 N 轮 / 共 Xm / 最近 …」全部从
`GET /api/people/:slug/turns?limit=30` 的 `startedAt` / `endedAt` 算（还在跑的轮次不计入
时长）；团队的「记忆 N 条 / 成员 N 人」来自 `GET /api/teams/:slug` 的 `memory.entries.length`
与 `ViewChannel.memberCount`。

**团队没有「今天 N 轮」**：轮次接口是按人取的（`/api/people/:slug/turns`），没有一个
「按频道取轮次」的接口 —— 把几个人的轮次加起来也不等于这个团队今天跑了几轮（同一轮可能
同时在两个频道里被人看到）。要画这个数就先补接口（§8.2），别在稿子上先算一个。
**算不出来就不画**，不要给个「—」占位。

### 13.3 两个去处（v6.1：不再有最左那一列）

应用级导航那一列删掉了（ADR-084）：首屏是助理对话，对话与列表的标题栏各有一颗
「设置」；插件在设置页里是一行，插件注册的 `rail.item` 入口也落在设置页。

- **后台任务不再是导航的一格**（2026-11-06 改）：它是右栏资料表里的最后一行
  （§13.2 第 8 行），点它右栏换态。理由：任务讲的是「这个人干了什么」，和资料讲的是
  同一个人 —— 放在同一栏里才是「换一种看法」，摆在导航里就成了「另一个地方」。
- **通讯录也不再是导航的一格**（同日）：团队和成员就是侧栏里的那些行，另开一屏只是
  把同一份列表再列一遍。手机上它本来就没有门（§13.7），桌面留着就两端对不上。

| 去处 | 两端同一摆法 |
|---|---|
| 聊天 | 首屏是助理对话；列表是它的第二屏（返回键回去） |
| **后台任务** | 资料页的一层：入口是资料表最后一行，返回回到资料 |
| 插件 / 设置 | 整屏一列（`.page`），左上角返回 |

**为什么资料与任务不再并排**（v6.1 改）：372 的浮层在窄窗口里要么挤压中列、要么和
空频道卡片抢层级；两个问题都来自「同一屏塞两件事」。一列到底之后，任何窗口宽度都不压缩、
不叠层，桌面与手机也只剩一套规则要维护。


> **状态**：**已落地**（2026-11-06，ADR-083）。`openTasks()` 打开右栏并置 `tasks.open`，
> `RightPanel` 用 `data-tasks` 换成 `TasksView`；手机上 `.detail` 本来就是整屏浮层。
> `App.tsx` 的 `view` 不再有 `tasks` / `team` 两值。
> 落地前，任何「桌面右栏显示任务」的截图都还是稿子。

### 13.4 桌面第一次打开（和手机同一段话）

引导页两端是**同一段文案**，只改排布：手机一列到底（标 → 一句话 → 三条说明 → 开始）；
桌面两列（左：标 + 一句话 + 开始 + 「下一步：接一个模型」；右：三条说明 + 两个根目录）。
**接模型页同理**：左栏说「它不产模型、跑在你选的这个上、密钥只在本机」，右栏是同一张
三选一的表 + 密钥 + 「就用这个」。桌面不额外加步骤，也不多问一个问题。

### 13.8 总览画布上的连线（只属于稿子）

`http://127.0.0.1:8791/v6/` 那张总览页把 21 屏手机和 8 屏桌面并排放，用线画出流转。
**这些线不进产品**，它们只是稿子的阅读辅助：

- **三种线**：实线 = 往下钻（主路径）；虚线 = 返回上一级；淡线 = 同一屏的另一种状态
  （浅色 / 未读 / 失败 / 等我选）。线的深浅就是「这条路径有多主」。
- **一律是曲线**：三次贝塞尔，横向相邻的两格也给一点弓高，不画水平直线。
- **不压卡片**：横向线只连同一行里相邻的两格；竖向线只连同列上下两行；跨好几行的跳转走
  每列左边留的那条空档（走廊），从卡片左沿拐进去、贴着空档弯下去、再拐进目标左沿。
  同一列的多条走廊各占一个 x，不互相压。
- **跨列不连**：手机列与桌面列之间没有线 —— 两端是同一张表的两种摆法，不是两个步骤。

改画布改生成器（`.superdesign/drafts/v6/` 的布局表），别手改生成出来的 `index.html`。
