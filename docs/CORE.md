# 核心：一套「组织是文件」的 agent 运行时

> 这份文档讲**为什么这样设计**和**它现在怎么运转**。
> 只看怎么跑起来 → [README](../README.md)；要改代码 → [CODE](CODE.md)；接口字段 → [WEB-API](WEB-API.md)。

## 0. 一句话

**组织是文件，不是代码。** 一个人就是一个文件夹；文件夹里的字决定他是什么人。

代码只做四件事：读文件夹、把文件夹投影成提示词、把消息写进频道、把频道推给界面。
除此之外的一切（谁是谁、谁向谁汇报、会什么、记住什么、团队做什么）都是磁盘上的
markdown。改组织 = 改文件 = 下一条消息生效，不重启、不重新部署、不改一行 TS。

这条原则有一个不能绕的例外，见 §3。

## 1. 一个人是什么

```
~/.solo/members/<slug>/          ← 我的组织：人、团队、技能、规矩
  identity.md                    ← 他是谁（唯一必需）
  memory.md                      ← 他记住了什么（他自己写、自己改）
  skills/<名字>/SKILL.md         ← 他会怎么做一件事
  workspace/                     ← 他只在这里干活（见 §5）

<appRoot>/assistant/<slug>/      ← 助理也是一个人，但住在应用私有那一边
  identity.md / memory.md / skills/ / workspace/
```

`identity.md` 只有三个可选的头字段：

```markdown
---
name: 林越
title: 技术负责人
team: demo
---

正文是你写的：职责、边界、工作方式。
```

**没有第四个字段，也没有身份枚举。** 谁是「技术负责人」不是代码决定的，是某个人在
`identity.md` 里写下的。

**组织是平的**（ADR-058）：没有 `manager`，没有谁向谁汇报。唯一的位置区别在**文件夹**
里 —— 助理住在应用根的 `assistant/` 下，成员住在用户根的 `members/` 下；`isAssistantDir`
是唯一判据，`assistantsOf` 是唯一出口。名字和 `title` 都能被他自己改，改完列表、侧栏
置顶、提示词都跟着走，但**改不了他是不是助理** —— 那是目录事实。

`title` 叫**身份**（身份标签），不是职业、岗位或职位分类 —— 它只是界面上显示的那一行字，
不决定能力，也不决定位置。组织里只有五个词：**我 / 助理 / 团队 / 成员 / 全员**。

**一个人只有一条会话**（会话键就是 slug）。身份、记忆、技能、模型、对话历史都只有一份。

## 2. 提示词是**投影**

V3 起，提示词 = **磁盘上的模板 + 磁盘上的事实**。`loadTemplates()` 读
`<appRoot>/prompt/NN-段名.md`，`renderPrompt()` 把「所有人 + 团队 + 技能目录 + 记忆目录 +
注册表里的全部工具」填进插槽。代码只剩排版（`src/core/md/prompt.ts`），「怎么说」全在
`seed/prompt/`。三个性质没变：

- **确定性**：同一组文件逐字节相同 —— 为了 prompt cache 不被打穿（cacheRead 便宜一个
  数量级，cacheWrite 更贵）。
- **不哄人**：填不上的插槽写「（未设置）」并报出来，不编造。报的两种原因分开：
  `unknown`（模板写了、装配没给 = 缺陷）、`unset`（给了、现在确实是空 = 事实）。
- **每次渲染都重读磁盘**（`agentSection` 的 `render` 是函数），所以改 `identity.md` /
  `memory.md` / `skills/` 之后**下一条消息就生效**。

这一条把「改我自己」和「改组织」变成同一个动作：写文件。

**工具自己说的话也在这条路上。** 8 个工具的描述、每个参数说明、拒绝与成功回话、投递头、
附件说明，同样不住在代码里：`<appRoot>/text/*.md`（`## key` 分节），代码只留键名
（`md/catalog.ts` 的 `fill(catalog, "say.refuse.pass")`）。差别只有一点：工具描述在**装配时**
定型，所以改 `text/tools.md` 要重启；`prompt/*.md` 仍是改完下一条消息生效。

**公共事实是渲染出来的，不是写下来的。** 每个人的提示词里都有「你在组织里的位置」
（助理是谁、在哪个团队、同团队的人、全员人数）。这段不存进 `identity.md` ——
组织会变，写死的话 agent 会按三周前的架构认真工作，而你看不出来它错了。

### 分段与前缀缓存

「一段提示词」在发给模型时其实是**八个段**，段名 = 文件名前缀，顺序 = 文件名顺序：

```
00-who → 10-rules → 20-position → 30-team → 40-tools → 50-memory → 60-skills → 70-directory
```

另有三段 `use: delivery`（`80-reply` / `88-task` / `90-interrupted`）**不进系统提示词**：
它们是某一轮贴给模型的话，由调用方每轮 `await` 读一次、当参数传给纯函数（不缓存，改模板下一条
消息就生效）。`88-task` 是插话那一轮贴给模型的正文。

- 每段一个 section key（`<slug>-<segment>`，`agentSections()`），内容没变的段就不发新版本。
- `tag: false`：tag 会往字节里加东西，加了就与前缀缓存对不上。
- **加一段 = 加一个文件**，不改代码。但顺序是语义（规矩排在能力前面），新增段或调序会触发
  一次性整块重写 —— 底座没有「某段失效」的钩子，只有按 key 的最小 patch。所以「加一段」
  不是免费操作。
- 确定性由 `npm run prompt:check` 守着：十段全渲染两遍，逐字节比对，未知插槽必须是 0 个。

这解释了为什么第 2、3 节说的「下一条消息就生效」是**按段**生效：改记忆只让 `memory`
之后的那几段重写，前面那几段（人人同款的规矩与工具清单）仍在缓存里。

## 3. 能力是**热**的，而且**不分层**

- 工具只有一套，人人都有（`registeredTools()` 直接从注册表实拍，不读任何清单文件）。
- 「你能调用的工具」这一段是注册表的投影：注册表里有什么就写什么。**不手写清单** ——
  手写的清单一定会漂，而漂了的提示词就是在撒谎。
- 新增能力 = 往注册表 `install` 一个 extension；不需要重新部署，也不需要改任何人的身份。
  想教 agent「怎么用这些手」，用**技能**，不要改代码。

**唯一的技术边界**：能力是**真代码**（一个函数）。`identity.md` 里写「你可以执行命令」
并不能凭空造出一个执行命令的工具。所以 —— **「能力是否存在」是代码，「用能力做什么」
是文档。** 这条边界绕不过去：让 agent 自己写代码然后执行，等于把机器交出去。

## 4. 通信是**平级**的

所有 agent 用同一套工具说话，没有「向上汇报」专用通道，也没有「管理层才能用」的工具：

**八个工具，一个动词一件事**。同一件事的几种做法是一个工具的
`action` 枚举，不是几个近义的工具名 —— 名字越多，模型选错的概率越高。

| 工具 | 作用 |
| --- | --- |
| `say` | 在频道说一句；带 `mention` 就是提问并叫醒对方；**没有「私下发给谁」这个参数** —— 私聊只能我开；`text` 写 `[PASS]` 表示这一轮不说（只有一个人的频道里会被拒绝）；「一轮只认一句结论」原来由代码强制，现在只剩 `rules.md` 约束 |
| `chats` | `action=list`（默认）= 我在的会话（标题、群聊/私聊、未读数、最后一条）；`action=read` = 读某个频道的历史消息；`action=create` = 拉一个群（`title` + `members`，我在里面） |
| `read_history` | `scope=channel`（默认）翻自己被压缩掉的历史对话（原文还在 storage 里，压缩后模型看不见）；`scope=memory`（或 `personal` / `team`）翻记忆全文 |
| `remember` | 记一条经验；`scope=team` 写团队记忆 |
| `hire` | 新建一个 agent（写文件夹 + 开会话 + 拉进全员频道与团队频道） |
| `route` | 助理专用：把频道里的一条消息在**后台**交给该看的人（默认 `seq` = 我刚被叫醒的那条）；频道里不出现「转交」 |
| `run` | 执行一条 shell 命令；`background: true` = 丢到后台跑（最多 30 分钟），跑完结果回到起跑的那个频道并叫醒起跑的人；`&` / `nohup` 是纯脱手，永远没有回音 |
| `file` | `action=read` / `write`：工作区里的一个文件 |

合并的口径一句话：`chats` 收回 `read_channel`，`read_history` 收回 `recall`（`scope`
区分翻对话还是翻记忆），`hire` 收回建人，`file` 收回读写两个工具，`org` 直接删掉（组织架构在
提示词的「你在组织里的位置」一节里，不在工具里）。**工具总数 17 → 11 → 7 → 8**：`teams` /
`write_team` / `skills` / `me` 四个是「用 `file` 读写某个固定路径 md」的包装，删掉之后
「改自己 = 写 `members/<slug>/identity.md`」才真正成立；后来加的第八个是 `route`
（团队频道的后台分发，ADR-063），它不是「另一种说法」，是现有工具都做不到的一件事：
**不往频道里写第二条消息，却把已有的那条交给另一个人**。

组织里谁在哪不靠工具查：它在提示词的「你在组织里的位置」一节里，
每次发送前从 `members/*/identity.md`（助理在 `assistant/*/`）现渲染。

**拍板没有中间层。** 职责范围内的事自己定；拍不了板的（花钱、超范围、改别人）在正文里
`@我`，说清要我定什么。让人替他转话，传一次丢一次。这条写在 `seed/rules.md` 与技能
「工作规矩」里，代码只保证事实（谁能收到消息），不保证纪律。

**组织变动归助理**：招人、开除、建团队、改别人身份，代码里只有助理能做
（`assistantsOf` 判据在工具入口）。这是权限，不是层级 —— 助理不是谁的上级，只是那个
能被 @ 到、替所有人统筹的人。

### 频道

`core.channels` 一份文档装全部频道：`Message{seq, from, at, text, mentions[], replyTo?, kind}`
+ `Channel{id, title, members[], wakeOnAll[]}`。收件人四条规则：

1. 显式 `@` 且是频道成员；
2. 我发言且没 `@` 任何人 → **我上一句话之后第一个接话的人**（他得在这个频道里、且不是
   我；系统留痕 `note` 不算接话）；我还没说过话、或紧接着是我自己说的，才退回「第一个
   非我的成员」（ADR-015）；
3. `wakeOnAll` 的成员；
4. 减去发件人自己。

**三种唤醒模型**（ADR-063），按频道形态分：

| 频道 | `wakeOnAll` | 谁看新消息 |
| --- | --- | --- |
| 团队频道 `team:<slug>` | 助理 | 助理每条都醒，判断跟谁有关，用 `route` 在后台交给那个人；频道里不出现「转交」，收件人看到原文，正文多一句「X 让你看这条」。已经被 `@` 的人不重复叫 |
| 组群 `group:<slug>` | 全部成员 | 每个人都收到，自己判断要不要接；无关就 `[PASS]` |
| 全员频道 `all` | 我 | 我醒；其他人只在被 `@` 时醒（全员广播不叫醒所有人） |
| 私聊 `dm:` | 空 | 对面那个人 |

`route` 只能助理用，写一条 `noteOf: "route"` 的隐藏留痕（「把 #N 交给谁看」）——
它是这一轮已经把消息交出去的凭据，收尾据此不再补发；界面不画（ADR-047）。
转给谁必须是这个频道里的成员，不能转给我、自己，也不能转给已经被 `@` 的人。

**`@` 只用来请求回复**：要对方回话才 `@`，只是提到名字就直接写名字。机制不变
（`parseMentions` / `recipientsOf` 照旧），这是写进 `rules.md` 与助理身份的纪律。

**引用回复等于 @ 作者**（`appendMessage` 里把被引用者并进 mentions）。`kind` 只有两种：
`chat` 发言、`note` 系统留痕。团队记忆不靠它自动整理 —— 谁认为值得记，谁用
`remember(scope=team)` 写。

**会话形态由 id 前缀 + 成员一起决定**：`chatKind()` 只把 **`dm:` 前缀且成员恰好
`{我, 一人}`** 认作 `dm`，其余一律 `group`；没有「个人频道」这种对象。团队频道就是
`team:<slug>` 这个普通的群，只是它有一份档案（见 §7）—— 即使只有我和一个 agent 两个人，
它也永远是群聊，投递正文不会写成「这是你和我的私聊」。

**组群是没有档案的群**：`group:<slug>`，任何成员都能拉（`chats action=create`；
我走 `POST /api/channels`）。建群的人自动在群里，至少两个人，同名不建第二份；
没有 README、没有团队记忆、没有负责人。人走光到只剩一个时自动归档（和私聊同一条清理规则）。

**每个成员都有自己的私聊**：装配 / 招人时自动建 `dm:<我, 他>`（`ensureOwnerDm`，幂等），
他的工作过程在那里看，群聊只留结论。私聊仍然是**我 ↔ 他**两个人的频道 —— 建它的是系统，
不是 agent：agent 之间不能私下找人，也没有「个人频道」这种东西。显式入口只剩
`POST /api/people/:slug/dm`（`openDirectMessage`，委托同一份实现）。团队频道与全员频道由
装配投影出来，组群由 `createGroup` 建（`POST /api/channels`）。除此之外没有别的地方能造出
一个没人投影的房间。

`@` 写的是**名字**，`mentions` 存的是 **slug**：`channel/mentions.ts` 的 `parseMentions` 只认
`slug` / `name` / `我` / `owner` **精确匹配**，其余（`@CEO`、拼音、title、`@老板`）
一律丢弃。**成员过滤不动** —— 别名只是翻译，不是放宽边界。`@` 前面只排除 ASCII 字母数字
与邮箱符号：中文不写空格，「麻烦@林越」必须认。两条说话规矩也
写在这里而不是提示词里：要找我拍板的事由 `say` 在两种情形下补 `owner`；投递
正文第一行写清频道 id，私聊额外说一句「只回这里」。没指明频道时 `fallbackChannelId` 只找
最近活跃的**真实**频道，`say` 的 `defaultChannel` 一旦发现兜底会落到私聊就**报错**，让模型
显式给 channel —— 不静默写进一个不存在的频道（这条踩过：话写成功了，频道里谁都看不见）。

**唤醒记录是两层的**：`reply` 是「这一句回哪儿」，`task` 是「手上那件活属于哪儿」。
我在他干活时私聊插一句，只改 `reply`，`task` 保留原来那个团队频道；不这样的话插话一结束，
团队再也等不到结论。两个频道相同时就简化为一条。

**结算即收尾**：一次提交结算成 `done` 时，若他**在这条唤醒之后没在目标频道说过话**，
`channel/turn/finish.ts` 就把答案条目里的最后一段正文替他说进频道；`unanswered` 则留一行痕。
「说过话」包括他自己发的 `note`：安静的一轮（`quiet`）里他的话就是留痕，不认它就会
把同一句再补发一遍（2026-11-02 周野的自我介绍在频道里并排出现了两条）。
**说过话不等于说完了**：还要看他这一轮**最后一个动作**是不是 `say`（`saidLast`）。是，说明
最后那段就是那句话换了个说法，不补；不是，说明他说完之后又干了活，最后那段是新结论，照补
（2026-11-02 陈默：被叫醒只是报个到，顺手把整个游戏写完了，频道里却只有开头那句自我介绍）。
「这条唤醒」按**这一次**的 `reply.seq` 算，不按 `task.seq`：插话一轮的 `task` 可能是很早
以前的那一条（下面那两层记录），拿它当起点会把上一轮的答案当成这一轮已经汇报过，
这一轮的结论就被吞掉了（2026-11-02 林越那次）。
唯一的例外是 `aborted`：那是**合并唤醒**撤掉了「还没开始」的排队项，消息还在频道里、
新的那一轮会把它们一起答，不是「没答上来」，不留痕。
V3 以前这里靠 6 秒定时器事后猜，现在结算本身就是信号，定时器删掉了。

**补发是一条真发言**（ADR-051）：它照常投递、照常叫醒被 `@` 的人 —— 否则「@周岚 请验收」
只是落进一个没人看的房间（2026-11-02 沈舟的交付结论就是这么丢的，团队停摆）。同一条答案
会被**多条提交**各结算一次（报到 + 投递、投递 + 后台命令跑完），所以补发前先比对：这个人在
这个频道里已经有一模一样的一句，就不再补（2026-11-02 周岚 #11/#12、沈舟 #15/#16，
相隔 1 毫秒）。
私聊插话那一轮：私聊已经答过 → 最终正文当作任务的结论回 `task`；否则回 `reply`。

**重启打断的那一轮会接着做**（ADR-044）：进程被杀时正跑到一半的会话（库里还留着
`pi.live` 的 `run`）由启动自愈结算成 `orphaned`，同时把「谁的这一轮断了」报给装配层；
装配层在**他当时干活的那个频道**留一句痕（`turn.interrupted`）并把他叫醒 ——
不叫的话，团队会停在那儿，频道里一片空白，和「还在干」长得一模一样。
没被打断的会话一个都不叫：正常重启不该让人白烧一轮。

**慢命令不占着一轮**：`run` 的前台最多等 300 秒，`&` / `nohup` 是脱手（起完就不管）。要「跑完告诉我」就用 `background: true` —— 起跑时把频道定下来，跑完由 `channel/jobs.ts` 把结果作为一条 `note` 发回那个频道，并用 `wakeTo` 叫醒起跑的人（`note` 默认谁也不叫，这是它唯一的例外，ADR-013）。最多跑 30 分钟，到点整组杀掉。服务重启时 `app/runs.ts` 把上一轮遗留的活结账：活着的杀掉、死掉的留一句话 —— 「跑完了」是进程内的回调，进程一死它就永远不会来，而等它的人看不出来。

**要我拍板时给选项**：`say` 带 `options`（2–6 个、不重复）时自动把我加进 `mentions` ——
选项是决策，不是「逐条列出」。回答**不新增路由、也不打标签**：我发的下一条消息就是答案
（`replyTo` 指向那条），正文就是选项文字；界面上还有一格「其他」可以自己写。界面的判定是纯函数
`ui/app/src/composer/choice.ts` 的 `pendingChoice()`（ADR-035）。会丢东西的动作（解散团队、
开除人、删文件或记忆）先这样问一句再动手，默认只归档不删 —— 语义在 `rules.md` 与「工作规矩」里。

**一条消息的长度看频道**：群聊 600 字、私聊 1200 字（`guards.ts` 的 `sayLimitOf`，ADR-014）。超了不落库，回一句「太长了」让它把过程写进文件、只发结论加路径。

## 5. 文件夹就是边界

**两个根**（ADR-030）：一个是**应用私有**（跟着这台机器上的这份安装走），一个是**我的组织**
（跟着我走）。拼路径只有 `layout.ts` 一处。

```
~/.solo/                        用户根：组织
  rules.md                      全员规矩
  skills/<名字>/SKILL.md        全员层技能：全员通用（写技能 / 找现成技能 / 工作规矩 / 记忆整理）
  members/<slug>/
    identity.md                 他是谁
    memory.md                   他自己的记忆
    skills/<名字>/SKILL.md      个人层技能：同名覆盖全员层
    workspace/                  他干活的地方
  teams/<slug>/
    README.md                   要做什么、什么不做、当前进展
    memory.md                   这个团队发生过什么（团队里的人写，全员能读）
    skills/<名字>/SKILL.md      团队层技能：这个团队的人都会，同名覆盖全员层
    workspace/                  团队任务干活的地方

<appRoot>/                      应用根：这份安装自带的东西
  assistant/<slug>/             助理（知言）本人，形状和 members/<slug>/ 一样
  prompt/                       提示词模板
  plugins/                      内置插件
  settings.json                 模型配置
  core.sqlite                   频道消息、会话、名册
  uploads/                      附件
```

「待在自己的工作区里」是**写在 md 里的纪律**，不是代码闸：代码只保证每个人/每个团队有一个
`workspace/` 目录，`run` 的默认 cwd 指向调用者自己的那份。

名册（`core.directory`）只是 slug ↔ 会话 id 的缓存，删了能从文件夹重建；**频道消息是
真历史，删了就没了**（它在应用根的 `core.sqlite` 里）。

读名册时**这次运行里开过的会话优先**，落盘那份只做兜底，缺人顺手补回去：落盘可能落后
（旧库、某次写丢了），只信它的话，工具会把人拒成「你还不在名册里」，重启还会给他换个新
会话、旧历史变孤儿（2026-11-02 周岚的私聊就是这么坏掉的：三个人只活在内核内存里）。

三级不是顺手分层，是**三种不同的变化频率**：全员通用做法几个月改一次、一个人的手艺
天天加、一个团队的坑一次就踩完。混在一起，改一处就得动全部。

| 归属 | 谁写 | 谁读 | 换了人还在吗 |
| --- | --- | --- | --- |
| `members/<slug>/*` | 他自己 | 他自己 | ✗ 跟着人走 |
| `teams/<slug>/memory.md` | 这个团队的人 | 全员 | ✓ 跟着团队走 |
| `skills/`（全员层） | 谁都能写（`scope=all`） | 全员 | ✓ |

另有一条纪律（不是代码约束）：**有 `bash` 的 agent 能读写全盘，包括别人的记忆**。
这是已知且被接受的 —— 隔离靠的是「目录归谁」的约定，不是沙箱。

## 6. 技能：能写成说明书的事就不写代码

一门技能是一个目录 + 一份 `SKILL.md`（YAML 头只有 `name` / `description`）：

- **`name` + `description` 常驻提示词**，正文按需 `skills(action=read)` 读。一个人攒 20 门手艺，
  常驻的是 20 行描述，不是 20 篇正文 —— 成本上最要紧的一条。
- agent 自己就能用 `file` 写出一门新技能（`members/<slug>/skills/<名字>/SKILL.md`），
  也能写团队共用的（`teams/<团队>/skills/<名字>/SKILL.md`）。
- 技能分三层，**下面的盖住上面的**：全员层 `<userRoot>/skills/` → 团队层
  `teams/<团队>/skills/` → 个人层 `members/<slug>/skills/`（助理那层在 `assistant/<slug>/skills/`）。一个人看到的是三层的并集，
  同名只留最靠下的那份，提示词里标「全员通用 / 团队共用 / 你自己写的」。
- **不必自己造技能市场**：`run` 跑 `npx skills find` / `npx skills add`，生态在
  skills.sh 和 GitHub。装完按我们的话重写一遍再用。
- 技能的正文**不在代码里**。播种源在 `seed/`：`seed/skills/` → 全员层，
  `seed/assistant/skills/` → 助理个人层。两份入口都**已存在的不覆盖** —— 播种只该发生一次。

判断边界：「做什么」是身份（`identity.md`），「怎么做」是技能（`skills/`），
「发生过什么」是记忆（`memory.md`）。三条都不在代码里。

## 7. 团队：一个有档案的群

`teams/<slug>/README.md` 的 YAML 头有 `name` / `doing` / `status`，正文写目标、
验收标准、什么不做、当前进展。`identity.md` 里写 `team: <slug>` 的人，提示词里自动出现
这份说明 + 团队里的人。**没有 `lead`**：团队里没有负责人这一层。

**团队 = 有档案的群。** 它不是一个和「人」并列的对象，而是频道的一种：`team:<slug>`
就是一个普通群聊频道，成员是这份档案的投影 —— 我 + 所有助理 + 所有 `team:` 指向它的人
（`channel/membership.ts` 的 `teamMembers`）。助理在每一个团队频道里：它是统筹者，
要看得见每个团队在做什么，团队里的人也要随时 @ 得到它。档案由 agent 写
`teams/<slug>/README.md` 修改；写成功后立刻重投影（`syncTeam`）—— 否则成员在团队
频道里 @ 不到刚进团队的人。

**团队频道由助理分发**（`wakeOnAll = 助理`，ADR-063）：每条新消息都先到助理，它判断
跟谁有关，再用 `route` 在后台把那条交给相关的人 —— 收件人收到原文，频道里不出现「转交」。
这替代了原来「没人被 @ 就叫醒负责人」：接话的是助理，不是「负责人」，它本来就该在这个
频道里；不这样设，agent 又会用 `run sleep 120` 轮询等进度（实测）。助理漏转一条，那条就
没人处理 —— 这是「助理负责阅读每一条」的代价，留痕让它可审计。

**开一个新团队只有助理能做**（`team/doc.ts` 的 `createTeamProblem`，写在 `file` 写
团队 README 之前）：成员发现需要新团队，在频道里 `@助理` 说清要做什么。改**已有**团队的
README 不受这条限制——改正文不是开摊子。`name` 缺省时退回正文的 `# 标题`，再缺才退回
目录名：标题是给人看的字，目录名（拼音）只是路径。

成员表是事实的投影，用整体替换而非只加不删，避免改名/重建后旧 slug 残留在成员表里变成
幽灵成员。

**新进来的人自己报到**（ADR-042）：`syncTeamChannel` 把这次新进频道的成员交出来，
装配层用一条系统留痕（`membership.joined`）叫醒他们 —— 团队一建好，成员各自说一句
自己是谁、负责什么，助理**不先说、也不替他们说**。只有运行时的重投影会叫；
启动时的重投影不叫，否则每次重启全体成员都白烧一轮。

**谁统筹、谁执行是技能里的语义**（`seed/assistant/skills/建立团队|招人`），代码不认识
「统筹」「执行」这些词 —— 它只认 `team:`（谁在哪个团队）和目录（谁是助理）。

**解散团队不写新工具**：把 README 的 `status` 写成 `archived` 就是解散 —— 团队频道被归档
（从列表消失，消息保留），团队目录与记忆原样留着。语义在 md 里，代码只做「README 说它
没了」这一件机械的事（ADR-033）。

**团队目录被删也是一样**：`run rm -rf teams/<slug>` 不会触发任何重投影，所以启动时扫一遍
（`archiveGoneTeams`），把没有 README 的 `team:` 频道归档 —— 历史留着，列表里不再出现。
人也可以先解散（README 归档）再删目录，两条路通向同一个结果。

全员频道（`all`）**不是特权频道**：它只是开机时播种一次的普通群，除了「人人都在
里面」以外没有任何特殊规则。「什么时候该建一个团队」是判断，写在知言的 `建立团队` 技能里。

## 8. 团队记忆

只有一条写路径：**主动**。agent 用 `remember(scope=team)` 写 `teams/<slug>/memory.md`
（`file` 直接写同一个文件也行）。能写的是这个团队的人，或者助理。没有自动沉淀了
（ADR-058 删掉了 `settle.ts`、`<管理员>#settle:<团队>` 影子会话与那套单游标）。

**为什么删**：一只眼睛盯着一千条消息去猜「哪条长期成立」，猜错的成本比漏记高；团队记忆
该是成员自己认为值得留下的东西。提示词与技能「记忆整理」仍然告诉它什么该记、什么不该记。

**安静的一轮里 @ 了人，就不安静了**：正文里点了谁（或 `say` 带了 `mention`），这条照常投递、
照常叫醒他 —— `note` 的语义是「留痕」，留痕不能顺手把话咽下去。

**合并唤醒只看会话**（ADR-048 收窄）：同一个会话里「还没开始」的排队项会被撤掉，最多留
一个；已经在跑的不碰。没有轻重之分了 —— 唤醒只有一个用途：叫这个人去干活。

**判断规则不在代码里**：什么该记、什么不该记、什么时候整理、记完怎么回话，都写在全员技能
「记忆整理」（`seed/skills/记忆整理/SKILL.md`）里 —— 人和 agent 都能改，改它不用改代码。



分工原则：**形状用代码判，语义用模型判**。代码判得准「这批消息还没整理过、也没被
整理者自己写过」，判不准「这句话是不是长期成立」；后者交给模型。

## 9. 界面

界面源码在 `ui/app/`（React + TypeScript + Vite），构建产物写回 `ui/web/`；
服务端只发 `ui/web/`。**改完界面必须 `npm run ui:build`**，源码改动不会自己出现在浏览器里。

```
ui/app/src/
  api/        fetch + SSE 客户端与后端类型的镜像
  state/      唯一状态源：一个 store + useStore
  stream/     buildRows() 纯函数算行，Stream.tsx 只负责画
  composer/   输入卡（@、附件、引用、输入法合成期不误发）；有待我选的选项时换成选项卡
  panels/     右栏（详情）、记忆抽屉、浮层
  sidebar/    左栏频道列表
  lib/        时间 / 头像 / Markdown / 合并消息 / 卡顿记录
  styles/     沿用 DSH 观感，类名不变
ui/web/       构建产物，服务端发这个目录，别手改
```

三条规矩：

1. **只画后端真的有的东西。** 没有待办就不画待办卡，没有 trace 就不留占位。为填满
   布局画一堆恒空的块，看的人分不清是「没有」还是「坏了」。
2. **状态单向。** 「谁跟谁算一段、气泡连不连、时间分隔插哪儿」全由纯函数 `buildRows()`
   算，视图状态写进 React state；不手工搬 DOM、不在 `dataset` 里存状态。
3. **样式类名沿用 DSH 观感**（`ui/app/src/styles/*.css`）。新样式加在对应文件里，
   别在组件里写内联样式或造第二套命名。

频道只有两种形态：`dm`（`dm:` 前缀且成员恰好是我 + 一个人）和 `group`（其余全部）。形态由
`channel/types.ts` 的 `chatKind()` 从 id 前缀与成员表算出来，`app/project.ts` 的投影直接映射，
核心没有「频道类型」这个概念。
团队就是一个 `group`：`team:<slug>` 只是它的 id，侧栏另外用 `team` / `doing`
两个字段把它标成团队。

**未读与「等我」分开**：侧栏频道行，`mentions > 0` 的红底是「等我说句话」，只有未读的是
浅灰底；点开频道 → 已读上报 → 列表重拉，红点当场清。**群头像画真头像**：左栏与右栏的
「活跃频道」都按 `channel.members` 拼（不是名册前四个），加人 / 换人后图标跟着变。

**附件与文件**：图片点开放大；其余附件点开先预览（按服务端发的真实 `Content-Type`：
图片 / PDF / `text/*` 内联，HTML 永远降成纯文本，其余说「不能预览，点下载」，ADR-037）。
右栏的「文件」页签是插件（`seed/plugins/文件树/`）：看当前频道那个工作区的目录树，点开
预览图片 / markdown / 代码 / HTML（沙箱 iframe）。

消息只有两种 `kind`：`chat` 发言、`note` 系统留痕（不画）。**过程不是消息**：旧版本写过的
`think` / `tool` / `work` / `step` 在投影层已经归一成 `note`，不再进聊天流；真的过程
（思考、命令、读写文件）来自轨迹（`ViewTurn.steps`），只在**后台任务面板**里画（ADR-062）：
聊天流里没有过程块，免得和面板重复。
**系统留痕（`note`）也不再画**（ADR-047）：报到、没答上来、看门狗
一律不进聊天流；唯一的例外是后台命令跑完那条（`noteOf: "run"`），它折成一行。
留痕仍在库里、`chats` 读得到，只是这一屏没有它 —— 灰字一屏插五六条，读起来像日志。

过程有两个出口，都不落库（ADR-046 / ADR-062）：**跑的时候**聊天流里有一条 `live` 占位（某个人
在这个频道被叫醒、还没回话；一行，写「做到哪一步」和正在跑的命令，跑完就消失）；**全部**
在这个人的后台任务面板里（最左「后台任务」那格：哪句话触发的、几步、各多久）。
步骤树只在后台任务面板里画，不造第二套展示。
没有「正在输入」的逐字草稿 —— C-007 没有 token 流，占位只报「做到哪一步」，不报「将要说什么」。

## 10. 目录

```
src/
  core/            ── domain（业务事实）──────────────────────────
    layout.ts        两个根的全部路径（拼路径只在这里）
    fsx.ts / naming.ts
    runtime/         openCore + 防腐层（唯一能 import pi-durable / pi-ai 的地方）
                     models（contextWindow / compaction）/ settings 也在这里
    md/              markdown / 插槽 / 提示词排版 / 文案目录 / 记忆格式
    agent/           identity（他是谁 + 新建一个人）/ sections（提示词九段装配）/ memory
                     skills / roster（slug ↔ 会话 + 两层唤醒记录）/ rules / secrets
    team/            doc（README.md）/ memory（memory.md）
    channel/         store（纯规则 + @ 解析）/ post（写一条 + 投递 + 唤醒）
                     wake（唯一唤醒入口）/ turn（结算收尾）/ attachments（附件）
                     tools（8 个工具）/ unanswered（结算原因翻成人话）
    plugin/          清单 / 四动作 API / 加载与隔离
  app/             用例：index（装配）/ types / snapshot / read / people / project（投影）
                   chat / uploads（附件语义）/ diag / errors
                   （不 import node:http，能脱离网络直接测）
  view/            dto.ts 一处定义界面吃的 JSON —— **契约层**，零 import
  interface/http/  唯一 import node:http 的地方：routes（路由表）
                   server（原语 + 匹配 + 来源闸 + 静态资源）/ sse（编解码 + hub）
  shell/           assemble（扫文件夹 → 开会话 → 建频道）/ serve（装配顺序 + 监听）
                   main（启动）/ seed
```

依赖只朝一个方向：`interface → app → domain`，`view` 谁都不依赖（大家都能用它），
`shell` 是唯一可以同时 import 全部的装配层。

`team/` 与 `agent/`、`channel/` **平级**：团队不是全员的子概念，它是与「人」并列的
另一种归属。

## 11. 开机做了什么

`npm start` 按顺序只做这几件事：

1. 同步 `rules.md` 与全员层技能（`seedRules` / `syncAllSkills`），并自检「记忆整理」
   技能在不在；
2. 读 `<appRoot>/settings.json` 里的模型，装配 `models` —— 同时从 pi-ai 的模型目录取
   **真实 `contextWindow`**（取不到回落 128k），据此算 compaction 阈值；
3. `createDiag(<userRoot>/logs)` —— 诊断落盘口（卡顿 `logs/jank.jsonl`、运行报告
   `logs/runtime.jsonl`）；
4. `openCore({ settings: { compaction }, onReport })` —— 打开 SQLite，并把底座的错误
   出口接成可读的报告：**失败不再静音**（crash-loop 把任务 park 成
   `blocked: restart_limit` 时，`GET /api/diag` 能看见原因）；
5. `assembleCore()` —— 扫两个 agent 根（`assistant/` + `members/`）→ 每人开一个会话 → 绑名册 → 建全员频道 →
   按 `identity.md` 的 `team:` 拉进团队频道；
6. `serveCore()` 起 HTTP + SSE；
7. 等 Ctrl-C。

用户根里还没有人时播种一个「离我最近的人」（`seedOwnerAssistant()`）—— 这是**唯一**
一处预置身份的地方，而且只写文件、不写代码。之后它自己 `hire` 别人。

**每个成员开机就有一条私聊。** 装配给每个人补 `ensureOwnerDm`（幂等）：私聊是他的
工作记录页，思考与工具调用在那里看。仍然没有「个人频道」—— 私聊是两个人的房间，
不是一个人的档案。

**刻意没有的东西**：看门狗、崩溃自愈、IM 出站、成本核算。
加回任何一样之前先问「不修它，系统会不会停摆」，答案是否就别加。

**没有消费者的概念不进内核。** 每一块代码要么被界面读、要么被模型读、要么被测试钉住行为；
只写不读的账本不是能力，是负债（ADR-060 删掉工单就是照这条判的）。一个概念也不要在两处
各有一套生命周期 —— 一条消息只有「落库 → 叫醒 → 回话」这一条。

## 12. 还没做的

- **成本**：没有。token 用量在 `TokenUsage` 里有，界面还没画。
- **看门狗 / 崩溃自愈 / IM 出站**：不为长跑兜底。「出事了看得见」这条已经有了：
  `onReport` + `logs/runtime.jsonl` + `GET /api/diag`，异常报告还会由 `app/watch.ts` 在
  全员频道留一条 `note`（ADR-016），重启时后台命令的账也会结掉（`app/runs.ts`）。缺的是
  **看见了之后的动作**：没有「判断谁没有实质进展、然后介入」的那一层，也没有崩溃自愈。
- **订阅直通**：团队频道里每条新消息都叫醒助理（`wakeOnAll`），回话跟着唤醒记录走
  （`defaultChannel`），我不 @ 人时接话的是接我上一句话的那个人（ADR-015）。但「多个 agent
  订阅同一件事、事件同时直通给所有人」这层没有 —— 一个频道默认只有一个人接话，
  要第二个人就显式 @。
- **模型看图**：附件能上传、能显示，但模型看不见图里的内容。
- **工作记录**：`GET /api/people/:slug/turns` 是后台任务面板的数据源（按人跨频道）；
  聊天流在哪儿都不画过程（ADR-062）。


## 13. 插件：一个文件夹，前后端各一半

`<appRoot>/plugins/<slug>/` 就是一个插件。它和 agent、团队是同一套形状 —— **加一个能力 =
建一个目录**，不改代码、不重建界面。

```
plugins/<slug>/
  plugin.md      YAML 头：name / description / enabled；正文是给人看的说明
  plugin.ts      后端：export function apply(api)     （可选；也可以写 plugin.js）
  client.js      前端：export default { apply(ui) }    （可选）
```

**后端四个动作**（`api`，插件源码里不 import 任何东西）：

| 动作 | 落了什么 |
|---|---|
| `tool({name, description, parameters, execute})` | 一个工具，和核心那七个进同一个注册表 |
| `prompt(text)` | 每个人提示词最后多一段（静态文本；塞时间戳会打穿缓存） |
| `route({method, pattern, handle})` | 一条 JSON 接口（GET / POST），排在静态兜底之前 |
| `on("message", …)` | 消息落盘之后、唤醒之前的一个回调 |
| `scope(channelId)` | 这个频道对应的目录（私聊 → 那个人的 `workspace/`，团队频道 → 团队 `workspace/`，全员频道 → 没有）。核心只给**根**，路径守卫 / 上限 / 拒符号链接都在插件里（ADR-036） |
| `logsRoot` | `<userRoot>/logs` 的绝对路径：审计（`tools.jsonl`）在这里，插件要按 token / 成本 / 耗时算账就读它（ADR-064）。和 `scope` 一样，核心只给根 |

**前端插槽**（`ui`）：界面上声明好的十几个缺口 —— 左栏头 / 列表上方 / 列表脚下、顶栏、
消息流上下、输入框右侧、右栏页签与底部、设置里多一节、全屏浮层层。全表见 `docs/DESIGN.md` §2.8。
插件拿到的是 `h`（`React.createElement`）、`React`、现有的接口客户端、界面状态 `store` /
`useStore` 和 `register`，看不到别的插件的模块 —— 跨插件协作只经插槽。
「能改哪里都」的做法是**把缺口声明出来**，不是让插件往 DOM 上贴东西：插件永远不用猜别人的类名，
宿主也不用为插件留一个万能钩子。

**为什么不是 dsh 那一套**：dsh 的插件能摸到 `ctx.tools` / `ctx.llm` / `ctx.sessions` 全部服务，
代价是插件必须懂 Cordis 的服务定位器和五种事件派发；Solo 的形态是「语义写在文档里，代码只做
机械的事」，所以给四个动作、每个动作只落一个数组。前端也简化掉了 boot 图与 lazy-CJS：
插件前端是一个普通 ESM 文件，`/api/plugins` 列出来，页面启动时 `import` 一次。
插槽是**启动时填一次就不变**的：没有订阅、没有热更新，改插件 = 刷新页面。

**隔离**：一个插件清单坏了、`import` 炸了、`apply` 抛了，都只是它自己的一条错误
（`/api/plugins` 里带 `error`），其它插件照装、服务照起。

**装在界面上**：左栏「团队管理」下面的「插件」列出 `<appRoot>/plugins/` 里的每一个
（名字、说明、它带来了什么、坏在哪），每行一个开关和一个「删除」，底下是装新插件的地方。

- **装 = 选一个文件夹**：插件的能力全在它自己的 `plugin.ts` / `client.js` 里，所以安装是
  把一个**已经写好的文件夹**整份搬进 `<appRoot>/plugins/<slug>/`。宿主先校验（名字不重、
  路径不越界、根上有 `plugin.md`）再一次落盘，不合格就一个文件都不写 —— dsh 的
  `inspect → install → 再启用` 也是这个顺序，只是它从包管理器拿，Solo 从磁盘上拿。
- **卸 = 删那个目录**：不可恢复，界面上二次确认。
- **开关**只改 `plugin.md` 头里的 `enabled`。
- 三件事都**当场生效**：写完文件就重装一遍插件（`shell/assemble.ts` 的 `reloadPlugins`，
  ADR-026）。重装做三件事 —— 按同名换掉 `core-tools` 扩展（会话按名字解析，下一次生成就看得见
  新工具）、重装每个人的身份扩展（插件段是装的时候拍下来的快照）、接口与消息钩子本来就每次现取。
  后端代码也是重装时按 mtime 绕开 `import` 缓存重新读的，所以改了 `plugin.ts` 也立刻生效。
  进程外面动 `plugins/` 目录（手写、`git checkout`）走 `shell/main.ts` 的文件监听，同样不用重启。
- 列表上那行「带来：工具 clock · 一段提示词」来自**这次进程真的注册出来的东西**。
  开着却没有 `brings`、也没有 `error`，说明后端入口没跑完或没装上 —— 界面上写「还没装上」。

**没有沙箱**：插件跑在进程里、页面里，等于本机全权限。它是我（或者 agent）自己写进工作区的
代码，信任是前提，不是漏洞 —— 但这意味着**不要装别人给的插件**。

**出厂插件**（`seed/plugins/`）：`模型管理` 在「设置」里多一节，读写 `<appRoot>/settings.json`
（字段见 `docs/DEPLOY.md` §3）—— 它是「插件够不够用」的第一块试金石：模型配置是文件 + 表单，
没有业务语义，正好不该长在内核里。`文件树` 在右栏画当前频道的工作区。要写新插件，契约在
`src/core/plugin/api.ts` 与 `docs/WEB-API.md` §13.4，不必先装一个样板。

**第一版不做**：插件市场、权限。前端 `client.js` 改了不用重启服务，但要**刷新页面**（浏览器里
那份 JS 已经跑起来了，换代码只能重新加载）。
