# Token 统计

在设置页加一行入口（`rail.item` 插槽），点开是一张 1040 宽的**用量弹窗**（`app.page` 插槽，
窄窗口铺满；底下的对话还在）。资料页最底下一格（`rightPanel.bottom` 插槽）是**这个人的**
近 7 天：七根小柱 + Token / 成本 / 缓存命中三个数，点一下进这张弹窗。

它回答三个问题：

- **最近花了多少** —— 7 天 / 30 天 / 全部三个档位下的计费 Token、输入与输出、缓存命中率、
  请求数与成本；
- **花在谁身上** —— 按人聚合，看一眼组织里谁最费上下文；
- **花在哪只模型上** —— 按模型聚合；再用 8 周热力图看自己实际在什么时候干活。

数据只有一个来源：`<userRoot>/logs/tools.jsonl`（ADR-010 的审计钩子，每次模型回复一行），
插件从 `api.logsRoot` 拿到目录。**不读会话数据库、不调用模型**，所以面板永远是当下的账。

口径（与 dsh-context 的 Context Insights 对齐，只保留 Solo 真有的字段）：

- 计费 Token = 新输入 + 缓存读 + 缓存写 + 输出；
- 缓存命中率 = 缓存读 ÷（新输入 + 缓存读 + 缓存写）；
- 成本 = provider 回报的美元金额，本地网关通常是 0。

审计只保留一份 5MB 的日志和一代轮转文件，所以「全部」也只是这两份里装得下的部分。

关掉它：`enabled: false`。
