# IM 机器人

参考 [dsh-im](https://github.com/xmanrui/dsh-im) 的形态，按 Solo 的插件契约做的一版：
**一个设置入口，管所有机器人**；每个机器人独立配置、独立开关、独立状态。

## 接的是什么

只接 **Solo 助理的那条私聊**（和用户确认过的范围）：IM 里发来的消息以「我」的身份落进助理私聊，
助理的回复再送回发消息的那个聊天。其他频道、团队成员都不参与 —— 这条链路只有一个收件人。

```
IM 聊天 ──收到──▶ 插件 ──api.post──▶ 助理私聊 ──助理回复──▶ 插件 ──▶ 原 IM 聊天
```

- 收到的消息带上来源：`[Telegram · 昵称] 正文`（群里再加群名），助理据此知道是谁在说。
- 回复路由：每条进来的消息把那个聊天记成「等回复」，助理在 **2 分钟**内的发言都送回那里。
  多个聊天同时说话时，助理的话会送到最近说话的那个 —— Solo 只有一条助理私聊，
  做不到 dsh-im 那样「每个聊天一条会话」，这是这版明确的边界。
- 只收文字（图片、文件、语音第一版不做）。

## 渠道

| 渠道 | 收 | 发 | 要什么 |
|---|---|---|---|
| Telegram | 主动拉取 `getUpdates`（本机就能用，不用公网地址） | `sendMessage`，长文按 3800 字分段 | @BotFather 给的 Bot Token |
| Webhook | `POST /api/p/im/in/<机器人 id>?token=…` | `POST <Webhook 地址>`，正文同时带飞书 / 钉钉 / 企业微信的字段形状 | 一个自定义机器人 Webhook 地址（+ 自己的接入方按上面那条路由推消息） |

Webhook 渠道对飞书 / 钉钉 / 企业微信的「自定义机器人」都能发（三家都用 `msgtype/msg_type + text`），
收消息需要你有公网入口把请求转到那条路由。Telegram 不需要公网入口，是这版的主力渠道。

## 访问控制

每个机器人两份设置：

- **私聊白名单**：留空 = 谁都能聊；填了只认这些 IM 用户 id（Telegram 是数字 id）。
- **群聊**：默认「被 @ 才回」，也可以改成「所有消息都回」。机器人自己发的消息、其他机器人
  的消息一律忽略。

## 数据放哪

`<appRoot>/im/bots.json`（机器人清单与凭据，权限 0600）。不放在插件目录里：出厂插件的升级判据
是整个目录的 hash（ADR-097），配置写进去会让插件永远「被改过」，再也升不了级。

## 不做什么

- 不做扫码建机器人、不做 OAuth 授权：dsh-im 那些流程都绑在它自己的平台上。
- 不做流式回复 / 过程卡片：Solo 的一轮就是最后那几条消息。
- 不做群聊天记录归档、文件回传、语音：第一版只把「说一句、回一句」接通。
