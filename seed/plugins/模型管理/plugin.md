# 模型管理

给「设置」浮层加一节**模型**，改的是 `workspace/settings.json`（字段含义见 `docs/DEPLOY.md` §3）。

- 列出每个 provider：名字、地址、协议、有没有密钥（**只显示尾号，不显示完整密钥**）。
- 「获取可用模型」真的去请求这个 provider 的 `/models`，把返回的 id 列出来让你挑，不用手抄模型名。
- 提供商与默认模型**保存后立刻生效**：内核在下一次读模型时就地重装注册表（ADR-025），不用重启
  （`src/core/runtime/models.ts` 的 `syncModels`），这份插件只负责写配置文件。
  「给某个人换模型」同样是当场生效的。
- 密钥留空 = 沿用已保存的那一份，所以改地址 / 改名字不会把密钥弄丢。
- 本地网关（`127.0.0.1` / `localhost`）的密钥可以不填，会存成占位符 `magpie`；
  **远端提供商没密钥直接拒绝** —— 存下来等于「配好了但用不了」，生成时才炸，
  界面上只看到「他这一轮没答上来」。
- **给某个人换模型**：私聊 / 人物档案的「详情」最上面（`rightPanel.detail` 插槽）有一个
  模型下拉，默认是「跟随默认」。换一只**当场生效**，并记进 `settings.json` 的 `agentModels`
  （重启也认）；走的是内核的 `POST /api/people/:slug/model`，插件只画这一行。

## 为什么是插件不是内核

模型配置是「一个文件 + 一层表单」，没有业务语义，也没有别的模块依赖它。
做成插件既不用为它改内核，也顺带证明插槽够用；内核只知道 `settings.json` 的格式。
